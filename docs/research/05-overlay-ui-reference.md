# 화면 위에 뜨는 UI: Godot 방식과 원작 배치 (2026-10-24)

사용자 지적(2026-10-24)에서 출발한 조사다.

- 「현재의 가장큰 문제점은 화면과 ui 테이블이 모두 각자의 고유영역을 가지고 있는 문제」, 차후 마을·상점도 같은 문제가 생긴다. 게임에서는 화면과 메뉴 영역이 나뉘지 않고 UI가 화면 위에 떠 있다(hover).
- 「레퍼런스 사진등을 찾아놓고 그 레퍼런스의 ui를 참조하지 않고 자체구현에 집착하는 행동이 계속된 ui 디자인의 개선을 방해하고 있음」 → 찾은 원작 디자인을 개선 지향점으로 삼는다.

research 03은 원작과 차이 목록(테두리·색·대비)을, research 04는 엔진의 그리기·입력 순서를 다뤘다. 화면 짜임 자체는 원작을 옮기지 않았고, 탐색의 시야 6 : 지도 4는 「HD와 같다」고 보고 그대로 두었다(research 03 「그대로 둘 것」). 이 문서는 그 판단을 바로잡는다. 원작 HD의 지도 판은 시야를 줄인 옆 칸이 아니라 화면 전체 시야 위에 덮이는 판이고, 기본 탐색 화면은 지도를 닫은 화면 전체 시야다(아래 §2).

### 1.2. 정리: 이 게임에 옮길 짜임

1. **세계는 늘 화면 전체.** 3D 시야(`SubViewportContainer`, `stretch`)·전투 배경·시설 그림은 화면 전체에 그리고, UI 때문에 줄이지 않는다. 두 예제 모두 세계(Node2D·카메라)는 화면 전체이고 UI는 그 위 `CanvasLayer`다.
2. **UI는 `CanvasLayer`로 층을 나눈다.** 예: 세계(층 0) → HUD(층 1) → 창(층 2: 지도 판·전투·캠프) → 모달(층 3) → 알림(층 4). 보이는 위아래 = 누르는 위아래(research 04: 고르기는 캔버스 층 → 트리 순서).
3. **층마다 화면 전체 크기 뿌리 Control 하나, `mouse_filter = IGNORE`.** 빈 곳 누르기는 아래(세계)로 간다(Open RPG `DialogueLayout`).
4. **HUD·창은 앵커로 화면 가장자리·모서리에 붙인다.** 좌표 계산(`_layout`) 대신 앵커 프리셋 + 여백(offset). 창 안 배치는 컨테이너. 넓은 화면(2400×1000 → 기준 1728×720)에서도 가장자리를 따라간다.
5. **문패·이름표는 음수 여백으로 창 테두리에 걸친다**(데모 대화창 이름 문패).
6. **옆 판이 시야 일부를 덮을 때는 시야를 줄이지 않고 렌즈를 민다.** `Camera3D.projection = PROJECTION_FRUSTUM`, 같은 세로 시야각이 되게 `size`(근평면 높이 = 2·near·tan(fov/2))를 주고, `frustum_offset.x`로 소실점을 덮이지 않은 영역 가운데로 옮긴다. 덮인 비율이 `p`(오른쪽)이면 소실점은 `(1 − p)/2`에 와야 하므로 `offset.x = (p/2)·근평면 폭`. 이 때 한쪽 시야 끝이 넓어지므로 카메라 보정 반경(05 §9.2.1)은 넓은 쪽 끝으로 잰 화면비를 쓴다.

### 2.3. 공통 규칙 (위 표에서 뽑음)

- 바탕은 언제나 화면 전체다. 전체 폭을 쓰는 것은 맨 위 메시지·설명 띠 하나뿐이고, 나머지(명령 목록·파티 카드·소지금·미니맵·위험 보석)는 바탕 위에 떠 있고 사이로 바탕이 보인다.
- 파티 카드 두 줄(위 전열·아래 후열, 엇갈림)은 마을 시설·전투·미궁 입구가 같은 부품이다.
- 명령은 왼쪽의 오른쪽이 굽은 목록(노랑 커서)이 기본이다(전투·시설 공통).
- 큰 판이 화면 한쪽을 덮는 것은 지도 판(오른쪽 약 43%)·캐릭터 판(상점·상태)처럼 「판 하나가 한 가장자리에 붙어 덮는」 모양이고, 그 때도 바탕은 줄지 않는다.
- 초상 그림은 판·창 테두리 위로 걸친다(상점 캐릭터 판·스킬 목록·전투 명령).

| 화면 | 지금 | 원작 |

| 파티 메뉴 | 화면 전체 불투명 창: 왼쪽 대원 카드 열 + 탭 + 내용 판(웹 대시보드 짜임) | 화면마다 다른 짜임(상태 판·스킬 목록·트리·상점형 장비)이고, 캠프 뿌리는 명령 목록 + 파티 카드(추정) |

| 전투 | 배경 전체 + 뜬 창(2.5단계). 명령 창은 오른쪽, 파티 카드는 한 줄 5장 | 명령 목록은 왼쪽(초상 위), 카드는 두 줄 엇갈림, 맨 위 메시지 띠, 오른쪽 아래 미니맵 |
| 마을·상점(M3) | 없음 | §2.2 「마을 시설」「상점」 |

## 4. 한계와 남은 확인

- 캠프 메뉴 화면은 확인하지 못했다(§2.2). 바꾸기 전에 확인하거나 사용자에게 묻는다.
- 그림 에셋(초상·창 무늬·위험 보석·적 그림)은 M3다. 그 전에는 같은 자리·크기의 자리표시(단색 실루엣 판 등)로 배치만 맞춘다.
- 이동 단추는 원작에 없다(휴대폰 터치 조작에 필요). 원작 안내 줄 자리(왼쪽 아래)에 반투명으로 둔다.
- `PROJECTION_FRUSTUM`·반투명 판이 웹(Compatibility) 렌더러에서 데스크톱과 같게 보이는지는 xvfb 캡처와 `web_check`로 확인한다.
