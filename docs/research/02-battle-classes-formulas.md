- **변경 분류:** 문서.
- **대상:** 세계수의 미궁 I~V, 신 세계수의 미궁(Untold, 이하 신1), 신 세계수의 미궁2(이하 신2), X(Nexus), I·II·III HD REMASTER/Origins Collection(2023).

- **조사 방법:** 공식 사이트·개발자 설명·공략 위키·공개 내부 분석 열람. 게임 실행, ROM 분석, 수치 재현 시험은 수행하지 않았다.

## 2. 조사 범위별 상세

### 2.1. 전투 흐름·행동 순서·기본 명령

아군의 명령과 대상을 정한 뒤 턴을 실행한다. 일반 행동은 적·아군이 속도에 따라 섞여 실행되지만, 최속·최후 행동과 지연 공격은 별도 처리된다. V 공식 명령 설명에는 공격·스킬·방어·아이템·대열 변경·유니온·도주가 포함된다. ([O02], [O06], 직접 읽음)

#### 행동 순서식

아래 수식은 모두 **추정**이다. S가 클수록 먼저 행동한다.

| 작품 | 공개 분석의 요약 | 근거·확인 |
|---|---|---|
| I DS | `S = floor(AGI × 기술 속도계수 / 5)`. 같은 5단위 구간에서는 무작위 순서. 일반 공격·방어·아이템의 계수는 1 | [W02] · 직접 읽음 |
| II DS | `S = (AGI + 무기 속도값) × 기술 속도계수 + 정수 난수 0~5` | [D02] · 직접 읽음 |
| III·IV | AGI에 장비·기술·속도 슬롯 보정을 더하는 계열 | [D03] · 직접 읽음 |
| IV 세부 | `S = AGI + 장비 속도 합 + 기술 속도값 + 2×SPD 슬롯 수 + 난수 0~4 + 2000` | [D03], [W16] · 직접 읽음 |
| X | `S ∝ AGI × 장비 합산 배율 × 기술 배율 × 기타 보정 × 난수 0.90~1.10` | [D05] · 직접 읽음 |
| 신1·신2·V·각 HD판 | 정확한 계산·절삭·동률 처리 **미확인** | 타 작품 식으로 대체하지 않음 |

I의 식은 원문의 구간 정렬 설명을 수식으로 정리한 것이다. 원문은 속도계수 계산 중 절삭도 명시한다. IV의 난수는 오래된 자료의 0~5와 최신 정리의 0~4가 다르므로 최신 분석을 우선했다. ([W02], [D03], 직접 읽음)

**특수 순서**

- I의 체이스 준비·아더스 스텝 등은 일반 속도 비교와 구별되는 최속 행동이다. ([W02], 직접 읽음)
- X의 Quick Step은 아군 행동을 앞당긴다. Sagittarius Shot은 착탄이 뒤의 턴으로 예약된다. ([D06], 직접 읽음)
- X의 레지먼트 레이브는 턴 마지막 공격으로 소개된다. 이 기술 상세는 검색 요약 수준이다. ([O03], 검색 결과 요약만 봄)

**기본 명령**

| 명령 | 확인 내용·주의점 | 근거·확인 |
|---|---|---|
| 방어 | IV·신1은 추정 0.5배. 신1은 독 피해도 줄이는 예외가 있음. I는 계산 중 내성값에 작용하므로 최종 피해 절반으로 단순화 불가 | [D03], [W25], [D01] · 직접 읽음 |
| 아이템 | 캐릭터의 행동을 소비. I의 사용 속도는 AGI 계수 1 | [O06], [W02] · 직접 읽음 |
| 도주 | 성공 확률·도주 불가 전투·강제 도주 기술을 구분해야 함. III·V에서는 다리 봉인이 도주를 막음 | [W14], [W24] · 직접 읽음 |
| 대열 변경 | IV는 명령 선택 단계에서 자유롭게 변경. I HD의 MOVE는 행동을 사용 | [W16], [W08] · 직접 읽음 |

방어 적용 시작 시점, 행동 취소 시 TP·아이템 소비 여부, 대상 사망 시 재지정, 작품별 도주 성공률 완전식은 **미확인**이다.

### 2.2. 대열·근접·원거리·적 대열

아군은 최대 5명, 한 줄 최대 3명인 전후열을 사용한다. 5인 편성에서는 3+2 또는 2+3이 대표적이다. 직업 소개의 “중위형”은 세 번째 아군 대열을 뜻하지 않는다. III의 분신·소환은 전투 중 여섯 번째 자리를 활용하고, V는 별도 소환열을 사용한다. ([W01], [W31], [O06], 직접 읽음)

적의 전후열은 IV에서 도입되었다. IV에서는 적 전열이 없어지면 후열이 앞으로 이동한다. I~III의 화면 배치에 후속작의 적 후열 규칙을 소급하면 안 된다. ([W16], 직접 읽음)

| 공격자 → 대상 | V 공식 근접 규칙 | 원거리 |
|---|---|---|
| 전열 → 전열 | 통상 사거리 | 가능 |
| 전열 → 후열 | 피해 감소 | 거리 감소 없음 |
| 후열 → 전열 | 피해 감소 | 거리 감소 없음 |
| 후열 → 후열 | 근접 공격이 닿지 않음 | 가능 |

근거: [O06] · 직접 읽음. V의 소환열은 거리 계산에서 전열로 취급된다.

**수치 차이**

- **I DS, 추정:** 후열의 비활 공격자는 STR을 절반으로 계산한다. 후열 대상은 근접 공격에 대한 VIT+장비 방어 합을 두 배로 계산한다. 최종 피해에 일괄 0.5를 곱하는 방식과 다르다. ([D01], 직접 읽음)
- **IV, 추정:** STR 의존 근접 공격의 거리 불이익은 0.5배로 정리된다. TEC 의존 여부와 사거리는 별도 속성이다. ([D03], 직접 읽음)
- **I:** 활은 원거리지만 채찍은 근접이다. 외형이 긴 무기라고 원거리로 분류하지 않는다. ([W06], 직접 읽음)

### 2.3. 능력치·성장·장비 슬롯

| 작품군 | 능력치 체계 | 근거·확인 |
|---|---|---|
| I~IV·신1·신2 | HP, TP, STR, TEC, VIT, AGI, LUC | [W01], [W16], [W25], [O15] · 직접 읽음 |
| V | HP, TP, STR, INT, VIT, WIS, AGI, LUC. TEC 대신 INT·WIS를 구분 | [W21], [W23], [D04] · 직접 읽음 |
| X | INT·WIS 체계를 사용 | [F07] · 검색 결과 요약만 봄 |

일반적으로 STR은 물리 공격, TEC/INT는 술식, VIT는 물리 내구, WIS는 마법 방어·회복, AGI는 속도·명중, LUC는 상태 판정에 관여한다. 그러나 기술마다 사용하는 능력치가 다르다.

**신2 공식 예외:** 활·총 공격은 AGI를 공격 능력치로 사용한다. 회복에는 TEC와 VIT, 실드 스마이트에는 STR와 VIT가 관여한다. 따라서 모든 기술을 `물리=STR`, `마법=TEC`로 나누면 부족하다. ([O15], 직접 읽음)

성장은 직업별 또는 종족별 고정 데이터로 관리된다. V는 전직해도 종족 능력치·종족 스킬을 유지하고, 이명이 추가 성장에 영향을 준다. ([W03], [W20], [W21], 직접 읽음)

장비는 통상 4칸을 사용하지만 머리·몸·손·발을 각각 의무 장착하는 방식은 아니다. IV의 보조 무기는 방어구 자리를 소비하며 포검에는 동시 장착 제한이 있다. I는 장신구 복수 장착이 가능하다. X의 종류별 중복 제한 상세는 검색 요약 수준이다. ([W16], [W07], 직접 읽음; [F04], [F05], 검색 결과 요약만 봄)

### 2.4. 피해 공식·크리티컬·명중·속성 내성

#### 개념 분리

피해 속성은 베기(斬)·찌르기(突)·때리기/타격(壊), 불·얼음·번개, 일부 무속성이다. **피해 속성, 의존 능력치, 사거리, 명중 판정 종류는 별개**다. 신1에는 STR 의존 원소 공격과 TEC 의존 물리 속성 공격이 존재한다고 분석되어 있다. ([W25], 직접 읽음)

내성표의 0.5는 피해 절반, 1.5는 피해 1.5배를 뜻한다. 상태이상 성공률용 내성과 분리해야 한다. III·IV·신1의 복합 속성은 유리한 피해 배율을 선택하는 방식으로 설명되지만, I에는 물리 항과 원소 추가 항을 따로 계산해 더하는 사례가 있다. ([D03], [W25], [D01], 직접 읽음)

#### 공개 피해식 — 모두 추정

다음은 비교용 축약식이다. 생략된 패시브·절삭·난수·최소 피해·예외까지 구현한 완전식은 아니다.

- `u`: 공격자
- `t`: 대상
- `wATK`: 사용하는 무기 공격력
- `gearDEF`: 장비 방어 합계

**I DS**

```text
물리 공격항 A = (uSTR + wATK) × 기술배율 × 속성배율 × 공격강화
물리 방어항 B = 0.5 × (tVIT + gearDEF) × 방어강화

술식 공격항 A = (2×uTEC + 기술 고유 공격력) × 기술배율 × 속성배율 × 마법강화
술식 방어항 B = 0.25 × (tVIT + gearDEF) × 방어강화

기초 피해 = A - B
이후 낮은 피해 구간 처리·난수·레벨 보정
```

크리티컬은 이 분석에서 **방어항을 0으로 만드는 효과**다. 보편적인 1.5배와 다르다. ([D01], 직접 읽음)

**II DS**

```text
W = 아군 공격자이면 무기 공격력/3, 적이면 uSTR
E = 아군 대상이면 gearDEF/3, 적이면 tVIT

A = (uSTR + W/2) × (20 + uSTR) × (20 + W)
B = (20 + tVIT) × (20 + E)

기초 피해 = 1.7 × A/B
이후 난수·기술·속성 보정
적 공격에는 0.8 보정
```

TEC 기술은 별도의 기술 위력값을 사용한다. 공개 분석은 TEC 피해 방어항에 대상 VIT 대신 **사용자 VIT가 들어가는 버그**를 명시한다. II HD 수정 여부는 **미확인**이다. ([D02], 직접 읽음)

**III·IV**

| 경우 | 기초 공격항 H, 최소 1 | 능력치 계수 Q |
|---|---|---|
| 아군 STR | `wATK - tVIT` | `sqrt(uSTR/tVIT)` |
| 아군 TEC | `4×uTEC - tVIT` | `sqrt(uTEC/tTEC)` |
| 적 STR | `3×uSTR - gearDEF/3` | `sqrt(uSTR/tVIT)` |
| 적 TEC | `5×uTEC - gearDEF` | `sqrt(uTEC/tTEC)` |

```text
피해 ≈ (H × Q × 기술배율 × 패시브·내성·강화 관련 항 + 난수 0~5)
       × 버프·디버프 관련 항
```

IV 내부 공식 가이드는 III와 IV의 대부분 계산을 함께 설명한다. 기술·장비 데이터까지 같다는 뜻은 아니다. ([D03], 직접 읽음)

**V — 아군→적 피해식의 공개된 일부**

```text
A = uSTR + wATK
B = 2×tVIT
q = B/A

q > 1:
  기초 피해 = 0.717 × {3A × (1 - 0.7×q^(1/4)) - 0.2B}

q <= 1:
  기초 피해 = 0.717 × {3A × [0.3 + 1.7×(1-q)^3] - 0.2B}

이후 기술배율 적용
```

INT 공격은 STR·ATK·VIT를 INT·MATK·WIS로 바꾼다고 분석자가 설명한다. 원문은 버프·패시브·난수를 제외한 **미완성 공개식**임을 밝힌다. 위 식은 원문의 단계별 계산을 기준으로 정리했다. 적→아군·최소 피해·절삭 순서는 이 자료만으로 확정할 수 없다. ([D04], 직접 읽음)

**신1·신2·X의 완전한 피해식은 미확인**이다. 신2의 공격 능력치 변경만 보아도 IV·V의 식을 그대로 적용할 수 없다.

#### 크리티컬·명중·회피

- 신1의 기본 크리티컬은 추정 1.5배다. IV 스나이퍼에는 활 기술도 크리티컬이 가능하게 하는 능력이 있다. ([W25], [W32], 직접 읽음)

### 2.11. 적 행동·봉인 대응·조건부 드롭

적 설계는 일반 몬스터·FOE·보스라는 분류만으로 끝나지 않는다. 조건부 행동, 다른 적과의 관계, 강공격 준비, 봉인 가능한 사용 부위가 전략을 만든다.

| 사례 | 전투 설계상 의미 | 근거·확인 |
|---|---|---|
| V의 멧돼지·도토리형 적 조합 | 다른 적을 먹고 강화되는 관계를 통해 처치 순서 유도 | [W22] · 직접 읽음 |
| IV 후반 보스의 본체·양팔 | 준비 행동 후 강공격, 팔 파괴에 따른 약화·중단, 부위 재생과 대열 변화 | [W30] · 직접 읽음 |
| II 지중의 습격자 | 주력 공격에 팔 사용 정보가 있으며 팔 봉인과 소재 조건이 연결 | [W33] · 직접 읽음 |

“봉인되면 다른 기술로 전환”과 “선택한 기술이 봉인 때문에 불발”은 다른 AI다. 모든 적이 어느 쪽으로 처리되는지 일반화할 근거는 부족하다.

**조건부 드롭 예시**

| 작품·적 | 공개된 조건 | 근거·확인 |
|---|---|---|

조건을 충족하는 것과 확률이 100%인 것은 별개다. 드롭 판정에는 처치 순간의 상태·봉인·마지막 피해 속성 등을 보존해야 한다.

FOE의 이동·난입 시점은 탐색 담당 범위다. 전투 쪽에는 난입할 적 편성, 합류 시점, 대열·선제 상태를 전달하는 연결 규칙만 필요하다.

### 2.12. 경험치·전멸·기상·부활

**기상과 소생은 구분한다.**

- 수면은 HP 0이 아니며 피해·자연 회복·치료로 해제된다. III에서는 피해로 깨어나도 그 턴의 행동을 되찾지 않는다. ([W14], 직접 읽음)

| 2 | 100 | 100 |
| 3 | 229 | 329 |

근거: [W32] · 직접 읽음.

**설계 제안:** I의 낮은 HP·TP 규모와 V의 높은 초기 수치를 섞지 않는다. 먼저 한 규모를 고르고 일반전의 예상 턴 수, 한 번의 실수로 잃는 HP, 회복 기술의 TP 효율을 함께 조정한다. 공개 표는 시작점이며 팬게임에서 검증된 밸런스가 아니다.

### 2.14. 원작 명칭·표현 사용에 관한 메모

이 절은 공개 자료 정리이며 법률 자문이 아니다.

한국저작권위원회는 아이디어와 창작적 표현을 구별한다. 미국 저작권청도 게임의 아이디어·진행 방법과 그림·문장 등 표현을 구분한다. 다만 미국 자료를 한국·일본의 개별 사안에 그대로 적용할 수는 없다. ([L01], [L02], 직접 읽음)

이름·짧은 문구가 저작권 보호 대상이 아니라는 설명과 상표 사용 가능 여부는 별개다. 상표에서는 외관·발음·의미와 관련 상품·서비스의 혼동 가능성 등이 문제된다. ([L03], [L04], 직접 읽음)

**설계 제안**

- 역할·턴 구조·전후열·자원 관리 같은 추상적 시스템을 분석하고 새 세계관·수치·기술 구성으로 다시 설계한다.
- 일반적인 직업 단어 하나와 원작의 고유 명칭·연출·그림·문구를 묶어 재현하는 일을 구별한다.
- 독자적인 직업명·스킬명·아이콘·설명문·UI·음악을 사용한다.
- 무료 배포나 비공식 표기만으로 이용 허락이 생긴다고 보지 않는다.

ATLUS가 이 형태의 팬게임을 포괄적으로 허용한다는 정책, 개별 명칭의 한국·일본 상표 등록, 관련 특허, 배포 형태별 판단은 **미확인**이다. 영상·방송 가이드라인이 팬게임 제작 허락까지 포함한다고 추정하지 않는다.

## 4. 구현 관점 메모

이 절은 **설계 제안**이다. 원작 엔진의 내부 구조를 확인했다는 뜻이 아니다.

### 4.1. 데이터 구조

Godot Resource 또는 JSON으로 정의 데이터를 보관하고, 전투 중 변하는 상태와 분리한다.

| 데이터 | 필요한 필드 |
|---|---|
| `RulesetDef` | 규칙 버전, 대열 보정, 피해식 ID, 절삭 정책, 상태 우선순위, 강화 슬롯 수, 전멸 정책 |
| `ClassDef` | 안정적인 ID, 표시명, 성장표, 장비 권한, 스킬 트리, 전용 능력 |
| `RaceDef` | 성장표, 종족 스킬, 초기 직업 제한 |
| `SkillDef` | ID, 최대 레벨, 선행 조건, 사용 부위, 요구 무기, 대상·사거리, 속도·우선순위, 레벨별 비용·효과 |
| `EquipmentDef` | 무기 종류, 기본 피해 속성, ATK/MATK/DEF/MDEF, 능력치·속도 보정, 소켓, 개별 착용 예외 |
| `EnemyDef` | 능력치, 속성·상태 내성, 행동 규칙, 기술, 경험치, 드롭 |
| `DropDef` | 소재 ID, 확률, 조건, 수량, 배타·동시 드롭 규칙 |
| `Evidence` | 작품·버전, 출처 URL, 확인 상태, 추정 여부, 조사일 |

런타임 상태는 다음처럼 별도 보관한다.

| 상태 | 예시 필드 |
|---|---|
| 유닛 | 현재 HP/TP, 생존 상태, 행·자리, 선택 명령 |
| 일반 상태이상 | 상태 ID, 적용자, 위력, 경과 턴, 해제 정보 |
| 봉인 | 머리·팔·다리 각각의 상태·경과 턴 |
| 강화·약화 | 효과 ID, 상쇄 그룹, 크기, 남은 턴, 적용·갱신 순서 |
| 누적 내성 | 대상×상태별 누적값, 마지막 적용 턴, 감소 규칙 |
| 특수 자원 | 개인/공유 게이지, 부스트 잔여 턴, 브레이크 사용 상태 |
| 예약 행동 | 착탄 턴, 대상 정책, 시전자 정보, 취소 조건 |
| 추격 | 트리거, 대상, 남은 횟수, 재귀 허용 여부 |
| 적 AI | 단계, 내부 턴 수, 준비 상태, 재사용 대기 |

### 4.2. 스킬 정의에서 분리해야 할 필드

```text
damage_elements: [slash, fire]
offense_model: strength_weapon
accuracy_model: agility
range_kind: melee
target_pattern: one_enemy
required_parts: [arms]
required_weapon_types: [sword]

priority_group: normal
speed_model: multiplier
speed_by_level: [...]
tp_by_level: [...]
power_by_level: [...]

hit_count: ...
per_target_hit_cap: ...
ailment_effects: ...
bind_effects: ...
buff_effects: ...
chase_trigger: ...
delay_turns: ...
```

불 속성이라고 INT 기술로, 활이라고 모든 기술을 원거리로 자동 판정하지 않는다. 명령의 사용 부위와 효과가 참조하는 능력치도 독립적으로 둔다.

### 4.3. 턴 처리 순서 제안

1. 턴 시작 효과와 예약 행동을 준비한다.
2. 아군 명령을 입력하고 비용·장비·대상 선택 가능 여부를 검사한다.
3. 적 행동을 선택한다. 조건 평가 시점을 규칙으로 고정한다.
4. 우선순위 그룹과 속도 점수로 행동 큐를 만든다.
5. 실행 직전 생존·상태·봉인·대상·사거리를 다시 검사한다.
6. 비용 지불과 명중·피해·부가 효과를 처리한다.
7. 사망·피격·추격·반격 이벤트를 처리한다.
8. 턴 종료 지속 피해·회복·상태 해제·강화 만료·냉각을 정해진 순서로 처리한다.
9. 승패·드롭·경험치·전투 후 상태를 확정한다.

이 순서는 원작 공통 정답이 아니다. 특히 독 사망과 회복의 선후, 마지막 적 사망 뒤 예약 효과, 비용 지불 시점은 팬게임에서 명시적으로 결정해야 한다.

### 4.4. 피해 계산 파이프라인 제안

```text
사용 기술·무기 확정
→ 대상·보호/대신 맞기 처리
→ 명중/회피 판정
→ 크리티컬 판정
→ 선택한 피해 모델의 기초 항 계산
→ 속성 내성·복합 속성 규칙 적용
→ 패시브·강화·약화·거리·방어 보정
→ 난수·절삭·최소/최대값 처리
→ HP 변화
→ 처치 순간 정보 저장
→ 부가 상태·추격·반격 처리
```

각 보정의 위치는 공식에 따라 다르다. I의 내성·방어항이나 IV의 난수 위치를 임의로 이동하면 결과가 바뀐다. 피해식마다 하나의 평가 함수를 두고, 중간 결과를 로그로 확인할 수 있게 한다.

### 4.5. 상태이상 판정 순서 제안

```text
대상 생존·효과 적용 가능 여부
→ 면역·현재 상태 우선순위 검사
→ 기술 기본 확률
→ 공격자/대상 능력치 보정
→ 대상별 내성·누적 내성·보정 적용
→ 확률 제한·난수 판정
→ 상태 교체·경과 턴 초기화
→ 누적 내성 갱신
```

피해 기술의 부가 상태가 빗나가도 판정되는지, 피해 0에서도 발동하는지, 여러 상태를 어떤 순서로 시도하는지는 기술별 규칙으로 둔다. 원작 전체의 동일 순서를 확인한 것은 아니다.

### 4.6. 적 AI·드롭·웹 저장 연결

- AI는 `조건 → 행동 후보 → 가중치/우선순위 → 대상 정책` 구조로 작성한다.
- 조건에는 턴 수, HP 비율, 동료 생존, 봉인, 준비 상태, 플레이어 강화 상태 등을 사용할 수 있다.
- 드롭 판정을 위해 마지막 타격의 속성, 처치 직전 상태·봉인, 처치 원인, 전투 턴 수를 보존한다.
- 탐색 담당과는 선제·기습·난입 편성·전투 종료 후 HP/TP를 교환한다.
- 시설 담당과는 경험치·소재·소생 비용·장비 해금에 필요한 결과만 교환한다.
- 저장 데이터에는 규칙 버전과 난수 상태를 포함해 재현 가능한 오류 보고를 돕는다.

최소 검증 사례는 전후열 사거리, 봉인 후 행동 불발, 상태 덮어쓰기, 네 번째 버프, 지연 공격 중 시전자 사망, 추격 재귀 차단, 조건부 드롭의 처치 순간 상태다. 이는 앞으로 구현할 때의 검증 제안이며 이번 조사에서 실행한 테스트가 아니다.

## 5. 미확인·논쟁 항목

1. **신1·신2·X의 완전한 피해식**, V의 적→아군 공식과 전체 절삭·최소 피해 처리.
2. **각 HD판의 내부 공식 동일성**, II TEC 계산 버그 수정 여부와 II HD 일반 FOE 경험치.
3. **행동 순서 세부:** 신1·신2·V·HD의 정확한 난수·동률 처리. IV는 오래된 0~5 자료와 최신 0~4 분석이 다름.
4. **누적 내성 감소:** V의 약 10턴 설명과 다른 위키의 8턴 초기화 요약이 일치하지 않음. 전 작품 공통값으로 채택 불가.
5. **턴 경계:** 방어 시작, 자연 해제, 독·재생, 부활 직후 행동, 전투 종료 직전 예약 효과의 정확한 순서.
6. **전 직업·장비 행렬:** 모든 작품의 개별 장비 착용 제한·중복 제한·특수 예외.
7. **성장 전체표:** 모든 레벨·직업·종족·은퇴 보정·최대 레벨 해금 조건의 완전 수록.
8. **신 시리즈·X 일부 세부:** 신1 특수 직업 해금 절차, 그리모어 전체 중첩 규칙, X 서브클래스 상세 일부는 원문 검증 부족.
9. **확률 전체표:** 도주·크리티컬·명중·상태 회복·게이지 증가·드롭 확률의 전 작품 전수 데이터.
10. **적 AI 전체:** 제시한 사례 외 전체 몬스터의 조건 분기·봉인 대응·난입 처리.
11. **권리 관계:** 팬게임 허용 정책, 개별 상표·특허, 한국·일본 등 관할별 배포 판단.
12. **프로토타입 적합성:** 공개 원작 수치는 팬게임에서 시뮬레이션·플레이테스트하지 않았다.

공식 설명서 전체와 모든 게임 버전의 동작을 확보한 조사는 아니다. Fandom 일부는 본문 접근 제한 때문에 검색 요약만 사용했고, 해당 항목에 이를 표시했다.
