# 마을·상점 (M3 R4)

원작 HD 상점 짜임(research 06 §2)을 옮긴다.

사용자 결정(D24, 2026-10-25):
- 가방은 지금처럼 쌓는다(07 §5.6).
- 소모품 갈래는 두되 빈 목록이다.
- 상점 화면을 먼저 만들고, 마을 골격 전에는 디버그 주소에서만 보이는 임시 입구로 연다.

단계는 S1 자료·규칙 → S2 부품 → S3 화면 → S4 마을에서 열기다. 이 문서는 지금 S1(§1~§6, 끝)과 S2(§7, 구현 메모 §7.8)를 정한다. S3·S4는 그 단계 전에 더하고, 그때까지는 research 06 §4가 제안이다.

값(값·판매값·시작 소지금·풀림 조건)은 모두 자체 값이고 밸런스는 나중이다. 원작 수치는 조사하지 못했다(research 06 §6).

## 1. 상점 정의(자료)

### 1.1. 장비 값·소재 판매값

- `data/items/equipment.json`: 장비마다 필수 `price`(구매값, 1~999,999 정수).
- 장비 판매값 = `price` ÷ 2(버림, 최소 1).
- `data/items/materials.json`: 소재마다 필수 `sell`(판매값, 1~99,999 정수).

### 1.2. 상점 파일 `data/shop/<이름>.json`

```json
{
  "id": "shop.junk_workshop",
  "name_key": "shop.junk_workshop",
  "stock": [
    {"item": "equip.training_sword"},
    {"item": "equip.ion_saber", "unlock": {"item.cable_scale": 3, "item.glow_scale": 1}},
    {"item": "equip.aegis_plate", "unlock": {"item.beetle_plate": 2, "item.intact_pincer": 1}, "limited": true}
  ]
}
```

키:
- `id`: `shop.` 접두. 다른 정의 ID와 겹치면 안 된다.
- `name_key`: 글자 표에 있어야 한다.
- `stock`: 줄이 1개 이상인 배열.

줄:
- `item`: 필수, 장비 ID. 소모품은 다음 단계다.
- `unlock`: 선택. 소재 ID → 1~999 정수. 없으면 처음부터 판다. 빈 사전이면 오류다.
- `limited`: 선택, 참·거짓. 참이면 `unlock`이 있어야 한다.

검사:
- 오류: 모르는 키, 모르는 장비·소재, 한 상점에 같은 장비 두 줄, `unlock` 없는 `limited`, 범위 밖 수, 타입이 다른 값.
- 경고(실패 아님): 어느 상점에도 없는 장비.

읽기:
- 정의 폴더(`res://data`) 종류에 `shop`을 더한다.
- 다른 정의와 같은 방식이다: 파일 경로 순, 키 검사, 파일 사이 참조 검사(`BattleDb`).

## 2. 상태

- `ExplorationState.money`: 소지금, 0~9,999,999 정수. 새 게임은 시작 소지금 200이다.
- `ExplorationState.shop`(`ShopState`):
  - `sold`: 소재 ID → 누적 판 수(1~9,999,999, 0이면 키를 두지 않는다). 줄지 않는다. 풀림은 이것으로 본다.
  - `pool`: 소재 ID → 한정 물건에 아직 쓰지 않은 수(1~`sold[소재]`, 0이면 키를 두지 않는다). 소재를 팔면 늘고, 한정 물건을 사면 준다.
  - `bought`: 한 번이라도 산 장비 ID의 집합.
- 상점이 하나라 상점 상태도 하나다. 상점이 여럿이 되면 상점 ID별로 나눈다.
- **풀림**: 진열 줄의 `unlock`에 적힌 소재가 모두 `sold`에 그 수 이상이면 풀린 것이다. 처음부터 파는 줄은 늘 풀려 있다. `sold`가 줄지 않으므로 한 번 풀리면 계속 풀려 있다.
- **한정 재고**(research 06 §2.6, 원작 「売った材料分しか買えず」): 풀린 한정 줄의 남은 수 = 소재마다 `pool[소재] ÷ unlock[소재]`(버림) 가운데 가장 작은 값.
- **NEW**: 풀렸고 아직 사지 않은 물건이다(`bought`에 없음). 원작 그림에서 추정했다(research 06 §2.3).

## 3. 규칙 함수 `ShopRules`

`src/core/shop/shop_rules.gd`(상태는 `src/core/shop/shop_state.gd`).

공통:
- 난수·시간·걸음을 쓰지 않는다.
- 거부하면 상태는 그대로이고, 사건 하나 `{type: "rejected", reason}`를 돌려준다.
- 받아들이면 부른 화면이 자동 저장한다(07 §8.5와 같다).
- 전투 중·전투 대기·전멸이면 `not_now`다(`GrowthRules`와 같은 때).

### 3.1. 읽기

- `catalog(defs, state, shop_id) -> Array[Dictionary]`
  - 풀린 줄만, 진열 차례로 돌려준다.
  - 줄: `{item, price, limited, stock, new, affordable}`. `stock`은 한정이면 남은 수, 아니면 −1이다.
  - 모르는 상점이면 빈 배열이다.
- `shortage(defs, state, shop_id, item_id) -> Dictionary`
  - 한정 줄을 하나 더 사려면 모자란 소재 → 수를 돌려준다.
  - 살 수 있거나, 한정이 아니거나, 모르는 물건이면 빈 사전이다. 원작 「…が足りません」 자리다.
- `buy_price(defs, item_id) -> int`
  - 장비의 `price`, 모르면 0이다.
- `sell_price(defs, item_id) -> int`
  - 장비 = `price ÷ 2`(최소 1), 소재 = `sell`, 모르면 0이다.

### 3.2. 사기 `buy(state, shop_id, item_id, qty) -> Array[Dictionary]`

판정 순서:
1. `not_now`
2. `unknown_shop`
3. `unknown_item`: 그 상점 진열에 없다.
4. `locked`
5. `bad_amount`: `qty`가 1~99 정수가 아니다. 참·거짓과 정수가 아닌 실수는 거부한다.
6. `sold_out`: 한정인데 남은 수가 `qty`보다 적다.
7. `no_money`: 소지금이 값 × `qty`보다 적다.
8. `bag_full`: 가방 개수 + `qty`가 99를 넘는다.

통과하면:
- 소지금에서 값 × `qty`를 빼고, 가방에 `qty`를 더한다.
- 한정이면 `pool`에서 `unlock × qty`를 뺀다(0이면 키를 지운다).
- `bought`에 더한다.
- 사건은 `{type: "bought", item, qty, cost, money}`다.

화면은 원작처럼 장비를 한 번에 하나씩 산다(S3). 규칙은 수량을 받는다(시험, 다음 단계 소모품).

### 3.3. 팔기 `sell(state, shop_id, lines) -> Array[Dictionary]`

`lines`는 `[{item, qty}]`다. 소재 또는 가방에 있는 장비를 판다. 장착한 장비는 가방에 없으므로 팔 수 없다(07 §5.6, research 06 §2.6).

판정 순서:
1. `not_now`
2. `unknown_shop`
3. `bad_lines`: 배열이 아니거나, 비었거나, 줄이 사전이 아니거나, 줄의 키가 `item`·`qty`가 아니거나, 같은 물건이 두 줄이다.
4. 줄마다 차례로:
   - `unknown_item`: 소재도 장비도 아니다.
   - `bad_amount`: 1~9,999 정수가 아니다.
   - `not_owned`: 가진 수보다 많다.
5. `money_full`: 소지금 + 판 값이 9,999,999를 넘는다.

통과하면 한 묶음으로 처리한다(research 01 §4.4):
- 물건을 뺀다(0이면 키를 지운다).
- 소지금에 판 값의 합을 더한다.
- 소재는 `sold`·`pool`에 판 수를 더한다(9,999,999에서 멈춘다).
- 사건 `{type: "sold", lines: [{item, qty, gain}], gain, money}`를 돌려준다.
- 이 판매로 처음 풀린 줄이 있으면 이어서 `{type: "unlocked", shop, items}`를 돌려준다. `items`는 진열 차례다.

장비를 팔아도 풀림·재고에는 들어가지 않는다. 원작은 소재를 팔아 풀린다(research 06 §2.6).

## 4. 저장 4판

- 머리: `schema` 4, `rules` `"m3s"`. 받는 쌍에 `4: "m3s"`를 더한다.
- `state`에 두 키를 더한다. 둘 다 정규화 문자열(해시)에 들어간다.
  - `money`: 정수.
  - `shop`: `{"sold": {}, "pool": {}, "bought": []}`. `bought`는 정렬한 배열로 쓴다.
- 검사:
  - `money`: 0~9,999,999 정수.
  - `shop`: 키가 정확히 셋이다.
  - `sold`·`pool`: 아는 소재 → 범위 안 정수.
  - `pool`의 키는 `sold`에도 있어야 하고 `pool[소재] ≤ sold[소재]`다.
  - `bought`: 서로 겹치지 않는 아는 장비 ID 문자열이다.
- 이전(07 §8.4와 같은 방식):
  1. 1·2·3판은 지금처럼 그 판 규칙으로 다 검사한다.
  2. 통과한 상태에 `money` = 시작 소지금, `shop` = 빈 상태를 넣는다.
  3. 원본 `saved_at`·`generation`으로 4판을 쓴다.
  4. 4판 읽기를 그대로 거친 결과만 돌려준다.
  - `from_schema`는 원본 판이다.

## 5. 시험(S1)

- **자료**:
  - 모든 장비에 `price`, 모든 소재에 `sell`이 범위 안에 있다.
  - 상점 파일 참조가 맞다.
  - §1.2 오류 갈래마다 하나씩 거부된다.
- **규칙**:
  - 진열: 잠긴 줄은 숨고, 처음부터 파는 줄은 보인다. NEW는 사기 전까지다. `affordable`.
  - 사기: 통과, 그리고 §3.2 거부 갈래마다 하나. 가방 99 경계, 한정 소모·바닥.
  - 팔기: 소재·가방 장비 통과, 장착한 장비는 `not_owned`, §3.3 거부 갈래마다 하나.
  - 풀림: 처음 한 번만 `unlocked`가 나고 진열 차례다. 여러 번에 나눠 판 소재도 누적된다. 한정 재고는 `pool`으로 다시 찬다.
  - 거부하면 정규화 상태가 그대로다.
- **저장**:
  - 4판 왕복(소지금·상점 상태 포함).
  - 1·2·3판 이전: 소지금 = 시작 소지금, 빈 상점.
  - 4판 검사 거부 갈래마다 하나.
  - 기존 저장 시험의 강도를 그대로 둔다.
- **새 게임**: 소지금 200, 빈 상점.

## 6. 구현 메모(S1, 2026-10-25)

명세가 정하지 않아 구현이 정한 것이다. 코드가 기준이다.

- **범위 이름**(`BattleLimits.RANGES`):
  - `price` 1~999,999, `sell` 1~99,999, `unlock` 1~999.
  - `money` 0~9,999,999.
  - `sold` 1~9,999,999: `sold`·`pool` 둘 다의 형식 범위다. `pool ≤ sold`는 따로 검사한다.
  - `buy_qty` 1~99, `sell_qty` 1~9,999.
  - 상수 `MONEY_MAX` = `SOLD_MAX` = 9,999,999.
- **시작 소지금** `ExplorationState.START_MONEY`(200):
  - `ShopRules`가 아니라 상태에 둔다. `ShopRules`는 이미 `SaveCodec.to_int`를 쓰는데, 이전(`SaveCodec`)이 시작 소지금을 쓰므로 `ShopRules`에 두면 서로 가리키게 된다.
- **자료 읽기**:
  - 상점 파일의 `id`·`name_key`·`stock`은 모두 필수다.
  - 접두는 `item` = `equip.`, `unlock` 키 = `item.`, `id` = `shop.`이다.
  - `limited: false`는 `unlock` 없이도 받는다.
  - 소재 판매값은 `BattleDb.material_sell`, 장비 값은 `EquipDef.price`, 진열은 `ShopDef`(`stock`·`stock_at`·`line()`)에 둔다.
  - 장비·소재 참조와 「어느 상점에도 없는 장비」 경고는 `_check_refs`가 본다.
- **4판 읽기 차례**: 대원 → 세계·지식·지도·조우·기타 → 일관성 → `materials` → `gear_bag` → `money` → `shop` → `battle`.
  - `bought`는 읽을 때 차례를 보지 않는다. 쓸 때 정렬하므로 해시는 차례와 상관없다.
  - 3판 파일에 섞인 `money` 같은 모르는 위 키는 전처럼 무시한다. 그때도 소지금은 시작 소지금이 된다.
  - 3판 검사 실패는 「3판 검사 실패: 」로, 다시 읽기 실패는 「3판 이전 결과 검사 실패: 」로 시작한다.
- **`ShopRules` 세부**:
  - `buy`·`sell`은 `defs`를 받지 않고 `state.defs`를 쓴다(§3.2·§3.3 꼴 그대로).
  - 공개 도움 함수 `unlocked(shop, line)`·`stock_of(shop, line)`가 있다.
  - `affordable`은 한 개 값 기준이다(재고·가방은 보지 않는다).
  - `shortage`는 잠긴 한정 줄에도 `pool`로 센다. 잠긴 줄은 진열에 없으므로 화면은 부르지 않는다.
  - 팔기 줄의 키는 정확히 `item`·`qty`다.
    - 같은 물건은 자료형까지 같은 값으로 가린다.
    - 문자열이 아닌 `item`은 `unknown_item`이다.
    - 줄 안의 판정 순서는 `unknown_item` → `bad_amount` → `not_owned`다.
  - `sold` 사건의 `lines`는 받은 차례이고, `qty`는 바꾼 정수다.
  - 수량은 정수와 같은 실수(`2.0`)도 받는다(`GrowthRules.supply`와 같다). 참·거짓, 정수가 아닌 실수, 문자열은 거부한다.
  - `sold`·`pool`은 같은 만큼 더하고 상한에서 멈추므로 `pool ≤ sold`가 유지된다. 소지금은 판 값을 다 받는다(넘으면 `money_full`로 거부).
  - `bought`는 「한 번이라도 산」 집합이라 팔아도 NEW가 돌아오지 않는다.

| `ShopFrame` 장식(설명 띠·문패·목록 창·설명 창) | 캠프와 같다(`left` = `PAD_SIDE` 232) | §2.2·§2.3 | — | 없음 |

- 트리 순서 = 그리는 순서 = 누르는 순서: 바탕 · 장식 · 목록 · 탭 줄 · 캐릭터 판 · 「뒤로」 · 상점 창.
- 상점 창은 상점 화면의 맨 뒤 자식이다(창 층 2). 캠프 확인 창(`PartyMenu` `Dialog`)과 같은 방식이다. 층 3 모달(오류 알림 등)은 그 위에 뜬다.
- 노랑은 커서 하나에만 쓴다(07 §9.2): 목록 줄 커서, 또는 창의 고른 단추.
  - 고른 탭은 하늘색(`checked`)이다.
  - 여러 개 고르기로 고른 줄도 하늘색이다. 원작은 노랑이므로 원작과 다른 점이다.
  - 상점 창이 떠 있으면 노랑은 창의 고른 단추 하나다. 목록의 커서 줄은 「켜진」 시안(`cmd:chosen`)이 된다. 여러 개 팔기 확인처럼 한 줄을 가리키지 않는 창이면 커서 줄을 그리지 않는다. 전투 명령 목록(`ListRow.chosen`)과 같은 방식이고, 바꾸는 쪽은 화면이다(§7.4 `set_cursor_mode`, 독립 검토 F3).

### 7.2. 종류 아이콘(`VectorIcons`)

- 이름: `kind_sword`·`kind_staff`·`kind_body`·`kind_shield`·`kind_head`·`kind_hands`·`kind_feet`·`kind_accessory`·`kind_material`(묶은 자루)·`kind_consumable`(물약 병).
- 원작 아이콘 모양을 단순한 선 그림으로 옮긴다:
  - 검은 비스듬한 날, 지팡이는 끝이 말린 막대.
  - 몸은 가슴 갑옷, 방패, 머리는 투구, 손은 장갑, 다리는 장화, 장신구는 반지.
- 한 가지 색으로 그리고, 28~40px에서도 서로 구별되게 한다.
- 그림 에셋(M3)이 생기면 바꾼다.

### 7.3. 탭 줄 `ShopTabs`

- 칸은 64×64 `TouchButton`이다: 뗄 때 한 번, 손가락 소유, `cancel()`.
- 「전체」 칸은 글자이고, 나머지는 아이콘이다(원작 「ALL」 + 아이콘).
- 고른 칸은 `checked`이고, 나머지는 어두운 남색이다. 노랑 커서는 쓰지 않는다.
- 신호는 `picked(index)` 하나다.
- 칸 차례: 갈래마다 `kind` 차례 표 하나(08 §1.3 차례와 같다).
  - 무기: 전체 · 검 · 지팡이.
  - 방어구: 전체 · 몸 · 방패 · 머리 · 손 · 다리.
  - 판매: 소재 · 장비 · 소모품(「전체」 없음).
- 원작과 다른 점: ZL·ZR 그림 칸이 없다. 키는 S3 키 표에 둔다.

### 7.4. 칸 목록 `ShopList`·`ShopRow`

- `PartyScroll` 안에 `ShopRow` 줄을 둔다. `ShopRow`는 `PartyButton`을 이어받아 그림만 더한다(캠프 줄 그림은 바꾸지 않는다).
- 줄은 64, 사이 4다. 끌기·휠·누르기 소유는 `PartyButton`과 같다.
- **줄 짜임**(원작 §2.3):
  1. 왼쪽 아이콘 칸: 어두운 남색 정사각형 + 종류 아이콘.
  2. 이름(왼쪽 맞춤).
  3. 「NEW」 주황 알약: 이름 오른쪽의 고정 칸으로, 원작처럼 줄마다 같은 x다.
  4. 오른쪽 맞춤 숫자: 구매는 값, 판매는 한 개 판매값.
  - 판매 줄은 이름 오른쪽에 작은 글자로 개수 「12개」를 붙인다. 쌓기 유지(D24)에 따라 원작과 다른 점이다.
- **상태**:
  - 커서 줄: 노랑(`selected`).
  - 흐림(`dimmed`): 돈 모자람·품절. 누르기는 받는다(이유는 S3가 알림 줄에).
  - 고른 줄(`checked`): 하늘색.
  - 품절 줄은 숫자 자리에 「품절」을 쓴다(원작 「NEED MORE!」는 보고만, research 06 §2.3).
- **빈 칸**: 목록 창에 보이는 줄 수만큼 칸을 채운다.
  - 남는 칸은 어두운 빈 줄과 빈 아이콘 칸이다. 장식이라 누르기를 받지 않는다.
  - 줄이 넘치면 오른쪽에 가는 위치 막대를 그린다(`BattleLogView.scroll_bar_rect`와 같은 그림).
- **API**:
  - `set_rows(rows)`: 줄마다 `{icon, name, new, right, count, dim, checked}`.
    - 지금과 같은 자료면 아무것도 바꾸지 않는다. 누르고 있는 손가락도 그대로다.
    - 자료가 다르면 줄을 바꾸기 전에 눌린 줄과 끌기를 모두 버린다. 그래야 앞 자료에서 누른 손가락이 바뀐 줄을 고르지 않는다(독립 검토 F1).
  - `cursor`, `set_cursor(i)`: 화면 안으로 맞춘다.
  - `set_cursor_mode(m)`: `"cursor"`(기본, 노랑) · `"chosen"`(커서 줄을 `cmd:chosen`) · `"none"`(커서 줄을 그리지 않음). 커서 자리와 내린 위치는 그대로다. 지금 모드는 `cursor_mode`로 읽는다. 이 필드에 바로 넣으면 줄 모양이 바뀌지 않으므로 화면은 함수를 부른다.
  - 신호 `picked(index)`, `cancel()`.

### 7.5. 상점 창 `ShopDialog`(수량·확인·알림 공용)

- 모양은 캠프 확인 창과 같은 창 그림이다. 단추는 `PartyButton` `skin = "cmd"`(고른 쪽 노랑 알약, 다른 쪽 청록)이고, 64 높이다.
- **확인**: 글 한두 줄 + 「예」·「아니오」(원작 YES·NO).
- **수량**:
  - 첫 줄: [아이콘] 이름 「N개」(원작 「メディカ ×10 ▲▼」).
  - 둘째 줄: 합계 문구.
  - 단추: 「-10」·아래 화살표·위 화살표·「+10」(64×64) + 「예」·「아니오」. 화살표는 `VectorIcons` `arrow`로 그린다.
  - 범위는 1~최대(부르는 쪽이 준다)이고, 끝에서 멈춘다. 원작의 감기는 미확인이다.
- **입하 알림**(원작 guide3 img3: 초록 창, 주황 물건 이름, (A) 닫기):
  - 머리 두 줄, 이어서 [아이콘] 이름 줄들(주황), 그리고 「확인」이다.
  - 줄은 최대 5개다. 넘치면 마지막 줄을 「외 n개」로 쓴다.
- 창이 뜨고 닫힐 때 부모(상점 화면) 안의 눌린 단추와 끌기를 모두 버린다. 캠프 `PartyMenu.cancel_pointers`와 같은 규칙이다(07 §9.4, 독립 검토 F2). 새 누르기는 창의 화면 전체 판이 막는다.
- 입력은 `handle(kind, arg)` 하나로 받는다. 단추 누르기도 같은 길이다.
  - `step`(±1·±10), `pick`(단추 사이 커서), `confirm`, `cancel`.
- 신호: `answered(yes: bool, qty: int)`. 알림은 `closed`.

### 7.7. 시험·캡처(S2)

- **부품 시험**:
  - 탭: 고르기·`checked`·`cancel`.
  - 목록:
    - 줄 수와 빈 칸 수가 목록 창 높이에 맞는다.
    - 커서를 맞추면 줄이 화면 안에 들어온다.
    - 흐림·고름 상태가 보인다.
    - 끌기는 고르기가 아니다.
    - 64px 이상이고, 글자가 잘리지 않는다(`clipped_parts`).
  - 창: 수량이 1~최대에서 멈추고, ±1·±10, 예·아니오 신호, 알림 줄 넘침.
  - 아이콘 10개가 그려진다.
  - 1280×720·1728×720에서 화면 안에 있고 캐릭터 판과 겹치지 않는다.
- **캡처**(조정자 확인, 원작과 나란히): 1280×720·2400×1000에서 넷이다.
  1. 구매 무기 「전체」(진열 실데이터, NEW·흐림 줄 포함).
  2. 구매 방어구 「방패」 탭.
  3. 판매 소재(개수, 고른 줄 하나).
  4. 수량 창과 입하 알림을 각각 띄운 화면.
- 캡처 도구는 /tmp에 둔다(저장소에 넣지 않는다).

### 7.8. 구현 메모(S2, 2026-10-25)

명세가 정하지 않아 구현이 정한 것이다. 코드가 기준이다.

- **`ShopFrame`**: 캠프 틀에 고를 수 있는 인자만 더했다. 기본값이면 캠프 그대로다(시험).
  - `build(prefix, back, with_desc, left_x, top = LIST_TOP)`. 탭 줄이 있으면 `top` = `TABS_LIST_TOP`(236).
  - `show_title(text, right = false)`: `right`이면 문패 글을 오른쪽에 맞춘다(오른쪽 여백 28, 글자색 `HEAD_TEXT`). 소지금 문패가 쓴다.
- **`ShopTabs`**:
  - 차례 표 `SETS`: 무기 [all, sword, staff], 방어구 [all, body, shield, head, hands, feet], 판매 [material, gear, consumable]. 판매 「장비」 칸 아이콘은 원작처럼 검(`kind_sword`)이다.
  - `TOP` = 166이고, 화면이 x = `ShopFrame.left`에 놓는다.
  - `setup(set, all_label)`은 칸을 다시 만들고 0번 칸을 고른다. `select(i)`는 신호를 내지 않는다. 칸을 누르면 `select` 뒤 `picked(i)`.
  - 칸 그림은 스킨 `shoptab`(어두운 남색)이고, 고른 칸은 공용 `checked`다.
  - 판매 탭은 원작처럼 아이콘만 그린다. `shop.tab.material`·`gear`·`consumable` 글은 S3가 쓸 수 있게 둔다.
- **`ShopList`·`ShopRow`**:
  - 줄 스킨은 `cmd`(청록 줄, 커서 노랑, 흐림 `cmd:disabled`)다. `cmd`에는 고름 모양이 없어 공용 하늘색 `checked`를 쓴다.
  - 고른 줄은 아이콘 칸 테두리도 굵은 하늘색(3px, `ShopRow.icon_edge()`)이라, 커서가 와서 노랑이나 `chosen`이 되어도 고른 것이 보인다.
  - `ShopRow.chosen`이면 `cmd:chosen`으로 그린다(전투 `ListRow.theme_state`와 같다). `ShopList.set_cursor_mode(m)`로 바꿔도 커서 자리와 내린 위치는 그대로다(필드 `cursor_mode`에 바로 넣으면 줄 모양이 그대로라, 화면은 함수를 부른다).
  - `set_rows`는 받은 자료를 깊이 비교(`==`)한다. 같으면 아무것도 하지 않고, 다르면 `cancel()` 뒤에 줄을 바꾼다.
  - 아이콘 칸 64×64, 이름 막대와 사이 4. 「NEW」 알약은 56×26이고 x = 이름 막대 왼쪽 + 16 + 232(숫자 칸 앞에서 멈춤)라 줄마다 같다(시험). 숫자 칸 폭은 80이다.
  - 빈 칸 수 = 목록 창에 다 들어가는 줄 수 − 줄 수. 다 들어가는 줄은 탭이 있으면 3(1280×720·1728×720 모두), 없으면 4다. 줄이 넘치면 다음 줄이 잘려 조금 보이고, 넘치지 않으면 마지막 빈 칸 아래가 비어 있다.
  - 위치 막대 자리(4 + 4)는 늘 비워 두어, 넘쳐도 줄 폭이 그대로다.
  - 줄을 누르면(뗄 때) 커서를 그 줄로 옮긴 뒤 `picked(i)`를 낸다.
  - 숫자는 세 자리 쉼표(`ShopRow.grouped`)이고, 값에도 쓴다. 판매 개수 「N개」는 기존 `party.count`를 쓴다.
- **`ShopDialog`**:
  - 폭 480, 확인 높이 200, 수량 268이고, 알림은 줄 수에 따른다. 목록 창 가운데에 놓고 화면 안으로 맞춘다.
  - 뒤는 검정 60%로 어둡게 하고 새 누르기를 막는다. 이미 눌린 손가락은 열고 닫을 때 버린다(§7.5).
  - 여는 함수: `open_confirm(text, yes_first = false)`, `open_qty(icon, name, unit, most, key = "shop.qty.buy", yes_first = false)`, `open_notice(shop_name, items)`.
  - 처음 커서는 「아니오」다(`yes_first` = false, 07 §4.6 캠프 확인 창과 같다). 원작은 YES가 먼저 노랑이다. S3에서 정한다.
  - `handle`:
    - `pick` 인자는 ±1이다.
    - `confirm` 인자는 단추 번호이고, 없으면 지금 커서다. 「예」·「아니오」 단추는 `confirm` 0·1로 온다.
    - `cancel`은 `answered(false, 수량)`이다.
    - 알림은 `confirm`·`cancel` 모두 `closed`다. 닫힌 창은 입력을 받지 않는다.
  - 수량 단추는 끝에서 흐려지고 노랑이 되지 않는다. 「±10」 글자 크기는 18이다(64 칸 안쪽 여백 안).
