# 마을·상점 (M3 R4)

원작 HD 상점 짜임(research 06 §2)을 옮긴다.

사용자 결정(D24, 2026-10-25):
- 가방은 지금처럼 쌓는다(07 §5.6).
- 소모품 갈래는 두되 빈 목록이다(M3 A4에서 채운다: 05 §17.5).
- 상점 화면을 먼저 만들고, 마을 골격 전에는 디버그 주소에서만 보이는 임시 입구로 연다.

단계는 S1 자료·규칙 → S2 부품 → S3 화면 → S4 마을에서 열기다. 이 문서는 지금 S1(§1~§6, 끝), S2(§7, 끝, 구현 메모 §7.8), S3(§8, 구현 메모 §8.14)를 정한다. S4는 M3 A2a에서 했다(§8.1). S3·S4는 그 단계 전에 더하고, 그때까지는 research 06 §4가 제안이다.

값(값·판매값·시작 소지금·풀림 조건)은 모두 자체 값이고 밸런스는 나중이다. 원작 수치는 조사하지 못했다(research 06 §6).

## 1. 상점 정의(자료)

### 1.1. 장비 값·소재 판매값

- `data/items/equipment.json`: 장비마다 필수 `price`(구매값, 1~999,999 정수).
- 장비 판매값 = `price` ÷ 2(버림, 최소 1).
- `data/items/materials.json`: 소재마다 필수 `sell`(판매값, 1~99,999 정수).

### 1.2. 상점 파일 `data/shop/<이름>.json`

```json
{
  "id": "shop.junk_workshop",
  "name_key": "shop.junk_workshop",
  "stock": [
    {"item": "equip.training_sword"},
    {"item": "equip.ion_saber", "unlock": {"item.cable_scale": 3, "item.glow_scale": 1}},
    {"item": "equip.aegis_plate", "unlock": {"item.beetle_plate": 2, "item.intact_pincer": 1}, "limited": true}
  ]
}
```

키:
- `id`: `shop.` 접두. 다른 정의 ID와 겹치면 안 된다.
- `name_key`: 글자 표에 있어야 한다.
- `stock`: 줄이 1개 이상인 배열.

줄:
- `item`: 필수, 장비 ID 또는 소모품 ID(`use.`, M3 A4, 05 §17.5).
- `unlock`: 선택. 소재 ID → 1~999 정수. 없으면 처음부터 판다. 빈 사전이면 오류다.
- `limited`: 선택, 참·거짓. 참이면 `unlock`이 있어야 한다.

검사:
- 오류: 모르는 키, 모르는 장비·소재, 한 상점에 같은 장비 두 줄, `unlock` 없는 `limited`, 범위 밖 수, 타입이 다른 값.
- 경고(실패 아님): 어느 상점에도 없는 장비.

읽기:
- 정의 폴더(`res://data`) 종류에 `shop`을 더한다.
- 다른 정의와 같은 방식이다: 파일 경로 순, 키 검사, 파일 사이 참조 검사(`BattleDb`).

## 2. 상태

- `ExplorationState.money`: 소지금, 0~9,999,999 정수. 새 게임은 시작 소지금 200이다.
- `ExplorationState.shop`(`ShopState`):
  - `sold`: 소재 ID → 누적 판 수(1~9,999,999, 0이면 키를 두지 않는다). 줄지 않는다. 풀림은 이것으로 본다.
  - `pool`: 소재 ID → 한정 물건에 아직 쓰지 않은 수(1~`sold[소재]`, 0이면 키를 두지 않는다). 소재를 팔면 늘고, 한정 물건을 사면 준다.
  - `bought`: 한 번이라도 산 장비 ID의 집합(M3 A4부터 소모품 ID도, 05 §17.11).
- 상점이 하나라 상점 상태도 하나다. 상점이 여럿이 되면 상점 ID별로 나눈다.
- **풀림**: 진열 줄의 `unlock`에 적힌 소재가 모두 `sold`에 그 수 이상이면 풀린 것이다. 처음부터 파는 줄은 늘 풀려 있다. `sold`가 줄지 않으므로 한 번 풀리면 계속 풀려 있다.
- **한정 재고**(research 06 §2.6, 원작 「売った材料分しか買えず」): 풀린 한정 줄의 남은 수 = 소재마다 `pool[소재] ÷ unlock[소재]`(버림) 가운데 가장 작은 값.
- **NEW**: 풀렸고 아직 사지 않은 물건이다(`bought`에 없음). 원작 그림에서 추정했다(research 06 §2.3).

## 3. 규칙 함수 `ShopRules`

`src/core/shop/shop_rules.gd`(상태는 `src/core/shop/shop_state.gd`).

공통:
- 난수·시간·걸음을 쓰지 않는다.
- 거부하면 상태는 그대로이고, 사건 하나 `{type: "rejected", reason}`를 돌려준다.
- 받아들이면 부른 화면이 자동 저장한다(07 §8.5와 같다).
- 전투 중·전투 대기·전멸이면 `not_now`다(`GrowthRules`와 같은 때).

### 3.1. 읽기

- `catalog(defs, state, shop_id) -> Array[Dictionary]`
  - 풀린 줄만, 진열 차례로 돌려준다.
  - 줄: `{item, price, limited, stock, new, affordable}`. `stock`은 한정이면 남은 수, 아니면 −1이다.
  - 모르는 상점이면 빈 배열이다.
- `shortage(defs, state, shop_id, item_id) -> Dictionary`
  - 한정 줄을 하나 더 사려면 모자란 소재 → 수를 돌려준다.
  - 살 수 있거나, 한정이 아니거나, 모르는 물건이면 빈 사전이다. 원작 「…が足りません」 자리다.
- `buy_price(defs, item_id) -> int`
  - 장비의 `price`, 모르면 0이다.
- `sell_price(defs, item_id) -> int`
  - 장비 = `price ÷ 2`(최소 1), 소재 = `sell`, 모르면 0이다.

### 3.2. 사기 `buy(state, shop_id, item_id, qty) -> Array[Dictionary]`

판정 순서:
1. `not_now`
2. `unknown_shop`
3. `unknown_item`: 그 상점 진열에 없다.
4. `locked`
5. `bad_amount`: `qty`가 1~99 정수가 아니다. 참·거짓과 정수가 아닌 실수는 거부한다.
6. `sold_out`: 한정인데 남은 수가 `qty`보다 적다.
7. `no_money`: 소지금이 값 × `qty`보다 적다.
8. `bag_full`: 가방 개수 + `qty`가 99를 넘는다. **M3 A4a부터: 공용 가방 60칸에 `qty`개가 다 들어가지 않는다(`BagRules.fit`, D31, 05 §17.2).**

통과하면:
- 소지금에서 값 × `qty`를 빼고, 가방에 `qty`를 더한다.
- 한정이면 `pool`에서 `unlock × qty`를 뺀다(0이면 키를 지운다).
- `bought`에 더한다.
- 사건은 `{type: "bought", item, qty, cost, money}`다.

화면은 원작처럼 장비를 한 번에 하나씩 산다(S3). 규칙은 수량을 받는다(시험, 다음 단계 소모품). 소모품은 수량 창으로 산다(M3 A4b, 05 §17.10).

### 3.3. 팔기 `sell(state, shop_id, lines) -> Array[Dictionary]`

`lines`는 `[{item, qty}]`다. 소재 또는 가방에 있는 장비를 판다. 장착한 장비는 가방에 없으므로 팔 수 없다(07 §5.6, research 06 §2.6).

판정 순서:
1. `not_now`
2. `unknown_shop`
3. `bad_lines`: 배열이 아니거나, 비었거나, 줄이 사전이 아니거나, 줄의 키가 `item`·`qty`가 아니거나, 같은 물건이 두 줄이다.
4. 줄마다 차례로:
   - `unknown_item`: 소재도 장비도 아니다.
   - `bad_amount`: 1~9,999 정수가 아니다.
   - `not_owned`: 가진 수보다 많다.
5. `money_full`: 소지금 + 판 값이 9,999,999를 넘는다.

통과하면 한 묶음으로 처리한다(research 01 §4.4):
- 물건을 뺀다(0이면 키를 지운다).
- 소지금에 판 값의 합을 더한다.
- 소재는 `sold`·`pool`에 판 수를 더한다(9,999,999에서 멈춘다).
- 사건 `{type: "sold", lines: [{item, qty, gain}], gain, money}`를 돌려준다.
- 이 판매로 처음 풀린 줄이 있으면 이어서 `{type: "unlocked", shop, items}`를 돌려준다. `items`는 진열 차례다.

장비를 팔아도 풀림·재고에는 들어가지 않는다. 원작은 소재를 팔아 풀린다(research 06 §2.6).

## 4. 저장 4판

- 머리: `schema` 4, `rules` `"m3s"`. 받는 쌍에 `4: "m3s"`를 더한다.
- `state`에 두 키를 더한다. 둘 다 정규화 문자열(해시)에 들어간다.
  - `money`: 정수.
  - `shop`: `{"sold": {}, "pool": {}, "bought": []}`. `bought`는 정렬한 배열로 쓴다.
- 검사:
  - `money`: 0~9,999,999 정수.
  - `shop`: 키가 정확히 셋이다.
  - `sold`·`pool`: 아는 소재 → 범위 안 정수.
  - `pool`의 키는 `sold`에도 있어야 하고 `pool[소재] ≤ sold[소재]`다.
  - `bought`: 서로 겹치지 않는 아는 장비 ID 문자열이다(M3 A4b부터 아는 소모품 ID도 받는다, 05 §17.11).
- 이전(07 §8.4와 같은 방식):
  1. 1·2·3판은 지금처럼 그 판 규칙으로 다 검사한다.
  2. 통과한 상태에 `money` = 시작 소지금, `shop` = 빈 상태를 넣는다.
  3. 원본 `saved_at`·`generation`으로 4판을 쓴다.
  4. 4판 읽기를 그대로 거친 결과만 돌려준다.
  - `from_schema`는 원본 판이다.

## 5. 시험(S1)

- **자료**:
  - 모든 장비에 `price`, 모든 소재에 `sell`이 범위 안에 있다.
  - 상점 파일 참조가 맞다.
  - §1.2 오류 갈래마다 하나씩 거부된다.
- **규칙**:
  - 진열: 잠긴 줄은 숨고, 처음부터 파는 줄은 보인다. NEW는 사기 전까지다. `affordable`.
  - 사기: 통과, 그리고 §3.2 거부 갈래마다 하나. 가방 99 경계, 한정 소모·바닥.
  - 팔기: 소재·가방 장비 통과, 장착한 장비는 `not_owned`, §3.3 거부 갈래마다 하나.
  - 풀림: 처음 한 번만 `unlocked`가 나고 진열 차례다. 여러 번에 나눠 판 소재도 누적된다. 한정 재고는 `pool`으로 다시 찬다.
  - 거부하면 정규화 상태가 그대로다.
- **저장**:
  - 4판 왕복(소지금·상점 상태 포함).
  - 1·2·3판 이전: 소지금 = 시작 소지금, 빈 상점.
  - 4판 검사 거부 갈래마다 하나.
  - 기존 저장 시험의 강도를 그대로 둔다.
- **새 게임**: 소지금 200, 빈 상점.

## 6. 구현 메모(S1, 2026-10-25)

명세가 정하지 않아 구현이 정한 것이다. 코드가 기준이다.

- **범위 이름**(`BattleLimits.RANGES`):
  - `price` 1~999,999, `sell` 1~99,999, `unlock` 1~999.
  - `money` 0~9,999,999.
  - `sold` 1~9,999,999: `sold`·`pool` 둘 다의 형식 범위다. `pool ≤ sold`는 따로 검사한다.
  - `buy_qty` 1~99, `sell_qty` 1~9,999.
  - 상수 `MONEY_MAX` = `SOLD_MAX` = 9,999,999.
- **시작 소지금** `ExplorationState.START_MONEY`(200):
  - `ShopRules`가 아니라 상태에 둔다. `ShopRules`는 이미 `SaveCodec.to_int`를 쓰는데, 이전(`SaveCodec`)이 시작 소지금을 쓰므로 `ShopRules`에 두면 서로 가리키게 된다.
- **자료 읽기**:
  - 상점 파일의 `id`·`name_key`·`stock`은 모두 필수다.
  - 접두는 `item` = `equip.`, `unlock` 키 = `item.`, `id` = `shop.`이다.
  - `limited: false`는 `unlock` 없이도 받는다.
  - 소재 판매값은 `BattleDb.material_sell`, 장비 값은 `EquipDef.price`, 진열은 `ShopDef`(`stock`·`stock_at`·`line()`)에 둔다.
  - 장비·소재 참조와 「어느 상점에도 없는 장비」 경고는 `_check_refs`가 본다.
- **4판 읽기 차례**: 대원 → 세계·지식·지도·조우·기타 → 일관성 → `materials` → `gear_bag` → `money` → `shop` → `battle`.
  - `bought`는 읽을 때 차례를 보지 않는다. 쓸 때 정렬하므로 해시는 차례와 상관없다.
  - 3판 파일에 섞인 `money` 같은 모르는 위 키는 전처럼 무시한다. 그때도 소지금은 시작 소지금이 된다.
  - 3판 검사 실패는 「3판 검사 실패: 」로, 다시 읽기 실패는 「3판 이전 결과 검사 실패: 」로 시작한다.
- **`ShopRules` 세부**:
  - `buy`·`sell`은 `defs`를 받지 않고 `state.defs`를 쓴다(§3.2·§3.3 꼴 그대로).
  - 공개 도움 함수 `unlocked(shop, line)`·`stock_of(shop, line)`가 있다.
  - `affordable`은 한 개 값 기준이다(재고·가방은 보지 않는다).
  - `shortage`는 잠긴 한정 줄에도 `pool`로 센다. 잠긴 줄은 진열에 없으므로 화면은 부르지 않는다.
  - 팔기 줄의 키는 정확히 `item`·`qty`다.
    - 같은 물건은 자료형까지 같은 값으로 가린다.
    - 문자열이 아닌 `item`은 `unknown_item`이다.
    - 줄 안의 판정 순서는 `unknown_item` → `bad_amount` → `not_owned`다.
  - `sold` 사건의 `lines`는 받은 차례이고, `qty`는 바꾼 정수다.
  - 수량은 정수와 같은 실수(`2.0`)도 받는다(`GrowthRules.supply`와 같다). 참·거짓, 정수가 아닌 실수, 문자열은 거부한다.
  - `sold`·`pool`은 같은 만큼 더하고 상한에서 멈추므로 `pool ≤ sold`가 유지된다. 소지금은 판 값을 다 받는다(넘으면 `money_full`로 거부).
  - `bought`는 「한 번이라도 산」 집합이라 팔아도 NEW가 돌아오지 않는다.

근거 원작(research 06):

값은 1280×720 기준이고 앵커로 붙인다. 넓은 화면(1728×720)에서도 같은 규칙이다.

- 상점 창은 상점 화면의 자식이고, 그 뒤에는 가상 키패드만 둔다(창 층 2, §8.3). 캠프 확인 창(`PartyMenu` `Dialog` · 키패드)과 같은 방식이다. 층 3 모달(오류 알림 등)은 그 위에 뜬다.
- 노랑 채움은 커서 하나에만 쓴다(07 §9.2): 목록 줄 커서, 또는 창의 고른 단추.
  - 노랑 테두리는 커서가 아닌 표시다. 캠프의 스킬 초안·장비 화면 판의 칸과 같다. 상점에서는 캐릭터 판의 견주는 칸이다(§8.5). 원작은 그 칸을 노랑으로 채운다(research 06 §2.4, C).
  - 고른 탭은 하늘색(`checked`)이다.
  - 여러 개 고르기로 고른 줄도 하늘색이다. 원작은 노랑이므로 원작과 다른 점이다.
  - 상점 창이 떠 있으면 노랑은 창의 고른 단추 하나다. 목록의 커서 줄은 「켜진」 시안(`cmd:chosen`)이 된다. 여러 개 팔기 확인처럼 한 줄을 가리키지 않는 창이면 커서 줄을 그리지 않는다. 전투 명령 목록(`ListRow.chosen`)과 같은 방식이고, 바꾸는 쪽은 화면이다(§7.4 `set_cursor_mode`, 독립 검토 F3).

### 7.2. 종류 아이콘(`VectorIcons`)

- 이름: `kind_sword`·`kind_staff`·`kind_body`·`kind_shield`·`kind_head`·`kind_hands`·`kind_feet`·`kind_accessory`·`kind_material`(묶은 자루)·`kind_consumable`(물약 병).
- 원작 아이콘 모양을 단순한 선 그림으로 옮긴다:
  - 검은 비스듬한 날, 지팡이는 끝이 말린 막대.
  - 몸은 가슴 갑옷, 방패, 머리는 투구, 손은 장갑, 다리는 장화, 장신구는 반지.
- 한 가지 색으로 그리고, 28~40px에서도 서로 구별되게 한다.
- 그림 에셋(M3)이 생기면 바꾼다.

### 7.3. 탭 줄 `ShopTabs`

- 칸은 64×64 `TouchButton`이다: 뗄 때 한 번, 손가락 소유, `cancel()`.
- 「전체」 칸은 글자이고, 나머지는 아이콘이다(원작 「ALL」 + 아이콘).
- 고른 칸은 `checked`이고, 나머지는 어두운 남색이다. 노랑 커서는 쓰지 않는다.
- 신호는 `picked(index)` 하나다.
- 입력 입구 `route`(S3 검토 R1에서 더함): `ShopList.route`와 같다(§7.4). 있으면 칸 누르기는 `route.call(i)`만 부르고, 고른 칸과 `picked`는 그대로다.
- 칸 차례: 갈래마다 `kind` 차례 표 하나(08 §1.3 차례와 같다).
  - 무기: 전체 · 검 · 지팡이.
  - 방어구: 전체 · 몸 · 방패 · 머리 · 손 · 다리.
  - 판매: 소재 · 장비 · 소모품(「전체」 없음).
- 원작과 다른 점: ZL·ZR 그림 칸이 없다. 키는 S3 키 표에 둔다.

### 7.4. 칸 목록 `ShopList`·`ShopRow`

- **D28-b부터**: 줄·커서·커서 모양·`route`·`picked`·눌림 버림은 공용 목록(`InventoryList`, 07 §9.9 「D28-a 공용 목록 메모」·「D28-b 상점 목록 메모」)이 맡고, 줄 그림은 `ShopRowLook`이 `ShopRow`로 그린다. `ShopList`는 틀(끌어 내리는 영역 크기·막대 자리·빈 칸·위치 막대)이다. 끝에서 ↑↓는 커서를 옮기지 않고 손으로 내려 가려진 커서만 보이게 하며(입력 하나), 줄 자료가 바뀌면 커서 줄을 보이게 한다. 빈 목록의 커서는 −1이다. 판매 줄은 캠프 소지품과 같은 가방 줄(`BagRows`)이고 소재는 정의 자료 차례다. 귀중품(M3 A3)은 판매 줄에 나오지 않는다: 상점은 장비·소재 종류만 넘기고, 캠프만 `CAMP_KINDS`로 귀중품을 더한다.
- `PartyScroll` 안에 `ShopRow` 줄을 둔다. `ShopRow`는 `PartyButton`을 이어받아 그림만 더한다(캠프 줄 그림은 바꾸지 않는다).
- 줄은 64, 사이 4다. 끌기·휠·누르기 소유는 `PartyButton`과 같다.
- **줄 짜임**(원작 §2.3):
  1. 왼쪽 아이콘 칸: 어두운 남색 정사각형 + 종류 아이콘.
  2. 이름(왼쪽 맞춤).
  3. 「NEW」 주황 알약: 이름 오른쪽의 고정 칸으로, 원작처럼 줄마다 같은 x다.
  4. 오른쪽 맞춤 숫자: 구매는 값, 판매는 한 개 판매값.
  - 판매 줄은 이름 오른쪽에 작은 글자로 개수 「12개」를 붙인다. 쌓기 유지(D24)에 따라 원작과 다른 점이다.
- **상태**:
  - 커서 줄: 노랑(`selected`).
  - 흐림(`dimmed`): 돈 모자람·품절. 누르기는 받는다(이유는 S3가 알림 줄에).
  - 고른 줄(`checked`): 하늘색.
  - 품절 줄은 숫자 자리에 「품절」을 쓴다(원작 「NEED MORE!」는 보고만, research 06 §2.3).
- **빈 칸**: 목록 창에 보이는 줄 수만큼 칸을 채운다.
  - 남는 칸은 어두운 빈 줄과 빈 아이콘 칸이다. 장식이라 누르기를 받지 않는다.
  - 줄이 넘치면 오른쪽에 가는 위치 막대를 그린다(`BattleLogView.scroll_bar_rect`와 같은 그림).
- **API**:
  - `set_rows(rows)`: 줄마다 `{icon, name, new, right, count, dim, checked}`.
    - 지금과 같은 자료면 아무것도 바꾸지 않는다. 누르고 있는 손가락도 그대로다.
    - 자료가 다르면 줄을 바꾸기 전에 눌린 줄과 끌기를 모두 버린다. 그래야 앞 자료에서 누른 손가락이 바뀐 줄을 고르지 않는다(독립 검토 F1).
  - `cursor`, `set_cursor(i)`: 화면 안으로 맞춘다.
  - `set_cursor_mode(m)`: `"cursor"`(기본, 노랑) · `"chosen"`(커서 줄을 `cmd:chosen`) · `"none"`(커서 줄을 그리지 않음). 커서 자리와 내린 위치는 그대로다. 지금 모드는 `cursor_mode`로 읽는다. 이 필드에 바로 넣으면 줄 모양이 바뀌지 않으므로 화면은 함수를 부른다.
  - 신호 `picked(index)`, `cancel()`.
  - 입력 입구 `route: Callable`(S3 검토 R1에서 더함, `ShopDialog.route`와 같은 방식):
    - 비어 있으면 S2 그대로다. 줄을 누르면 커서를 옮기고 `picked(i)`를 낸다.
    - 있으면 줄 누르기는 `route.call(i)`만 부른다. 커서와 `picked`는 그대로다. 받을지는 화면이 정하고, 받은 뒤에 화면이 `set_cursor`를 부른다.
    - 끌기는 어느 쪽이든 고르기가 아니다. `set_rows`·`set_cursor_mode` 약속은 그대로다.

### 7.5. 상점 창 `ShopDialog`(수량·확인·알림 공용)

- 모양은 캠프 확인 창과 같은 창 그림이다. 단추는 `PartyButton` `skin = "cmd"`(고른 쪽 노랑 알약, 다른 쪽 청록)이고, 64 높이다.
- **확인**: 글 한두 줄 + 「예」·「아니오」(원작 YES·NO).
- **수량**:
  - 첫 줄: [아이콘] 이름 「N개」(원작 「メディカ ×10 ▲▼」).
  - 둘째 줄: 합계 문구.
  - 단추: 「-10」·아래 화살표·위 화살표·「+10」(64×64) + 「예」·「아니오」. 화살표는 `VectorIcons` `arrow`로 그린다.
  - 범위는 1~최대(부르는 쪽이 준다)이고, 끝에서 멈춘다. 원작의 감기는 미확인이다.
- **입하 알림**(원작 guide3 img3: 초록 창, 주황 물건 이름, (A) 닫기):
  - 머리 두 줄, 이어서 [아이콘] 이름 줄들(주황), 그리고 「확인」이다.
  - 줄은 최대 5개다. 넘치면 마지막 줄을 「외 n개」로 쓴다.
- 창이 뜨고 닫힐 때 부모(상점 화면) 안의 눌린 단추와 끌기를 모두 버린다. 캠프 `PartyMenu.cancel_pointers`와 같은 규칙이다(07 §9.4, 독립 검토 F2). 새 누르기는 창의 화면 전체 판이 막는다.
- 입력은 `handle(kind, arg)` 하나로 받는다. 단추 누르기도 같은 길이다.
  - `step`(±1·±10), `pick`(단추 사이 커서), `confirm`, `cancel`.
- 신호: `answered(yes: bool, qty: int)`. 알림은 `closed`.

### 7.7. 시험·캡처(S2)

- **부품 시험**:
  - 탭: 고르기·`checked`·`cancel`.
  - 목록:
    - 줄 수와 빈 칸 수가 목록 창 높이에 맞는다.
    - 커서를 맞추면 줄이 화면 안에 들어온다.
    - 흐림·고름 상태가 보인다.
    - 끌기는 고르기가 아니다.
    - 64px 이상이고, 글자가 잘리지 않는다(`clipped_parts`).
  - 창: 수량이 1~최대에서 멈추고, ±1·±10, 예·아니오 신호, 알림 줄 넘침.
  - 아이콘 10개가 그려진다.
  - 1280×720·1728×720에서 화면 안에 있고 캐릭터 판과 겹치지 않는다.
- **캡처**(조정자 확인, 원작과 나란히): 1280×720·2400×1000에서 넷이다.
  1. 구매 무기 「전체」(진열 실데이터, NEW·흐림 줄 포함).
  2. 구매 방어구 「방패」 탭.
  3. 판매 소재(개수, 고른 줄 하나).
  4. 수량 창과 입하 알림을 각각 띄운 화면.
- 캡처 도구는 /tmp에 둔다(저장소에 넣지 않는다).

### 7.8. 구현 메모(S2, 2026-10-25)

명세가 정하지 않아 구현이 정한 것이다. 코드가 기준이다.

- **`ShopFrame`**: 캠프 틀에 고를 수 있는 인자만 더했다. 기본값이면 캠프 그대로다(시험).
  - `build(prefix, back, with_desc, left_x, top = LIST_TOP)`. 탭 줄이 있으면 `top` = `TABS_LIST_TOP`(236).
  - `show_title(text, right = false)`: `right`이면 문패 글을 오른쪽에 맞춘다(오른쪽 여백 28, 글자색 `HEAD_TEXT`). 소지금 문패가 쓴다.
- **`ShopTabs`**:
  - 차례 표 `SETS`: 무기 [all, sword, staff], 방어구 [all, body, shield, head, hands, feet], 판매 [material, gear, consumable]. 판매 「장비」 칸 아이콘은 원작처럼 검(`kind_sword`)이다.
  - `TOP` = 166이고, 화면이 x = `ShopFrame.left`에 놓는다.
  - `setup(set, all_label)`은 칸을 다시 만들고 0번 칸을 고른다. `select(i)`는 신호를 내지 않는다. 칸을 누르면 `select` 뒤 `picked(i)`.
  - 칸 그림은 스킨 `shoptab`(어두운 남색)이고, 고른 칸은 공용 `checked`다.
  - 판매 탭은 원작처럼 아이콘만 그린다. `shop.tab.material`·`gear`·`consumable` 글은 S3가 쓸 수 있게 둔다.
- **`ShopList`·`ShopRow`**:
  - 줄 스킨은 `cmd`(청록 줄, 커서 노랑, 흐림 `cmd:disabled`)다. `cmd`에는 고름 모양이 없어 공용 하늘색 `checked`를 쓴다.

  - `set_rows`는 받은 자료를 깊이 비교(`==`)한다. 같으면 아무것도 하지 않고, 다르면 `cancel()` 뒤에 줄을 바꾼다.
  - 아이콘 칸 64×64, 이름 막대와 사이 4. 「NEW」 알약은 56×26이고 x = 이름 막대 왼쪽 + 16 + 232(숫자 칸 앞에서 멈춤)라 줄마다 같다(시험). 숫자 칸 폭은 80이다.
  - 빈 칸 수 = 목록 창에 다 들어가는 줄 수 − 줄 수. 다 들어가는 줄은 탭이 있으면 3(1280×720·1728×720 모두), 없으면 4다. 줄이 넘치면 다음 줄이 잘려 조금 보이고, 넘치지 않으면 마지막 빈 칸 아래가 비어 있다.
  - 위치 막대 자리(4 + 4)는 늘 비워 두어, 넘쳐도 줄 폭이 그대로다.
  - 줄을 누르면(뗄 때) 커서를 그 줄로 옮긴 뒤 `picked(i)`를 낸다.
  - 숫자는 세 자리 쉼표(`ShopRow.grouped`)이고, 값에도 쓴다. 판매 개수 「N개」는 기존 `party.count`를 쓴다.

  - 못 끼면 바뀐 값 없이 장비 줄을 흐리게 한다(원작 B).
  - 견주는 칸 `best_slot`(독립 설계 검토 F5):
    - 후보 차례: 무기는 칸 0이다. 방어구·장신구는 같은 종류 제한(방패·몸·머리·손·발 하나, 장신구 둘)에 닿았으면 그 종류가 든 칸을 번호순으로, 아니면 빈 칸을 번호순으로 놓고, 남은 칸 1~3을 번호순으로 잇는다(겹치면 뺀다).
    - 그 가운데 `GrowthRules.equip_block`이 빈 이유를 주는 첫 칸을 고른다. 모두 막히면 -1이다.
    - 사기 전 비교는 실제 상태를 바꾸지 않고, 가방 사본에 그 물건을 하나 더한 것으로 판정한다(사지 않은 물건이 `not_in_bag`으로 막히지 않게). 산 뒤의 장착 물음·칸 고르기는 실제 가방으로 다시 판정한다.
    - 바뀌는 값은 고른 칸을 바꾼 대원 사본의 `GrowthRules.profile`로 보인다(캠프 장비 화면과 같다). 실제 대원·가방은 바꾸지 않는다.
  - 견주는 칸의 노랑 테두리는 커서가 아닌 표시다(§7.1). 캠프 장비 화면과 같은 그림이다.
  - `CharPanel.show_member`가 `PartyMenu` 없이도 쓰이게 바꾼다. 이름 도우미를 함께 쓰는 곳으로 옮기고, 캠프 모양과 시험은 그대로 둔다.

### 8.6. 사기 흐름(장비는 한 번에 하나, research 06 §2.5)

줄을 누르거나 「선택」:
1. 사지 못하는 줄은 창 없이 설명 띠 둘째 줄에 이유를 보인다.
   - 돈 모자람: `shop.why.no_money`.
   - 품절: `shop.why.sold_out`. `shortage`의 소재와 수를 「네온 쥐 꼬리 3개」 꼴로 잇는다(`, `로).
   - 가방에 그 장비가 99개: `shop.why.bag_full`.
2. 확인 창은 `shop.confirm.buy`다. 판의 대원이 못 끼면 `shop.confirm.buy_unfit`이다.
   - 창 머리에 수량 창과 같은 [아이콘] 이름 줄을 둔다. 확인 창이 목록의 커서 줄을 덮기 때문이다. `open_confirm`에 아이콘·이름 인자를 더한다.
   - 첫 커서는 「예」다(D25). 목록 커서는 `set_cursor_mode("chosen")`(§7.1)이다.
3. 「예」 → `ShopRules.buy(state, shop, item, 1)`.
   - 거부면 이유(`shop.why.<reason>`)를 알림 줄에 보이고, 상태는 그대로다.
   - 받아들이면 자동 저장하고, 소지금 문패·줄(NEW 꺼짐·흐림)·판을 다시 맞춘다.
4. 산 뒤 실제 가방으로 `best_slot`이 0 이상이면 장착 물음 `shop.confirm.equip`(「예」 먼저)을 띄운다. 아니면 묻지 않고, 물건은 가방에 둔다.
5. 「예」 → 무기는 칸 0에 `GrowthRules.equip`. 방어구·장신구는 칸 고르기 창(§8.7)을 띄운다.
   - 받아들이면 자동 저장한다.
   - 거부면 이유를 알림 줄에 보인다(캠프 장비 화면의 막힘 이유 글과 같다). 산 물건은 가방에 남는다.
6. 끝나면 목록 커서는 같은 줄로 돌아오고, 모드는 `"cursor"`다.

- 확인 창 → 장착 물음 → 칸 고르기가 이어지는 동안 대상 물건과 대원은 확인 창을 연 때의 것으로 고정한다. 창이 떠 있는 동안 `Q`/`E`·판 화살표·탭·숫자 키·뒤 화면의 단추는 일하지 않는다.

### 8.7. 칸 고르기 창

원작은 오른쪽 판에서 칸을 고른다고 하나 보고만이다(research 06 §2.5). 판의 장비 줄은 누르기에 작아 읽기만 하므로(07 §9.7) 창으로 고른다. 원작과 다른 점이다.
- `ShopDialog`의 새 모드 `slots`:
  - 머리 `shop.slot.ask`.
  - 칸 1~3 줄: 64 높이, `PartyButton` `cmd`, 글 「방어구 1  패딩 코트」, 빈 칸은 「비어 있음」(캠프 문구 그대로).
  - 아래에 「아니오」.
- 막힌 칸은 흐리다(`GrowthRules.equip_block`이 이유를 주는 칸). 누르면 그 이유를 창 안 둘째 줄에 보인다.
- 첫 커서는 `best_slot`이다. ↑↓ 칸(끝에서 멈춘다), 「선택」은 그 칸에 끼기, 「취소」·「아니오」는 끼지 않기다(물건은 가방에 남는다).
- 결과는 칸 번호를 내는 신호(예: `slot_picked(slot)`)로 따로 알린다. `answered(yes, qty)`에 칸 번호를 싣지 않는다.
- 노랑은 창의 커서 하나다. 목록 커서는 `"chosen"`이다.

### 8.8. 판매 목록(원작 A img2·B, S3b)

- 짜임은 구매 목록과 같다. 탭 셋(소재·장비·소모품, 아이콘만)이고, 「여러 개」 단추가 더 있다.
- **줄**:
  - 소재 탭: `materials`(자료 차례).
  - 장비 탭: `gear_bag`(자료 차례).
  - 소모품 탭: 빈 목록, 설명 띠 둘째 줄 `shop.why.empty_sell`.
  - 줄 = `{icon, name, count: 「N개」, right: 한 개 판매값(세 자리 쉼표), checked: 여러 개로 고름}`.
- **한 줄 팔기**(여러 개 꺼짐): 줄을 누르거나 「선택」.
  - 가진 수가 2 이상이면 수량 창(1~가진 수, `shop.qty.sell`, 「예」 먼저)이다.
  - 1이면 확인 창(`shop.confirm.sell`, 머리에 [아이콘] 이름)이다.
  - 「예」 → `ShopRules.sell(state, shop, [{item, qty}])`.
- **여러 개**(원작 Y MULTI):
  - 「여러 개」 단추: 탭 줄 왼쪽 빈 곳(x 16, y 166, 200×64). 키는 `M`이다.
  - 켜면 단추 글이 `shop.multi.sell`(「고른 것 팔기」)로 바뀐다. 줄을 누르거나 「선택」은 그 줄의 고름을 켜고 끈다(하늘색 `checked`, 가진 수 전부).
  - 「고른 것 팔기」(또는 `M`): 고른 줄이 있으면 확인 창(`shop.confirm.sell`, 목록 커서 `"none"`)이다. 없으면 여러 개를 끈다.
  - 「예」 → 고른 줄 모두를 한 묶음으로 `sell`한다. 「아니오」면 고름이 그대로다.
  - 「취소」·`Esc`·「뒤로」는 고름을 지우고 여러 개를 끈다. 탭을 바꿔도 고름을 지운다.
- **끝난 뒤 상태**(독립 설계 검토 F1):
  - 「아니오」·취소: 창을 닫고 같은 탭·커서·내린 위치로 돌아간다. 여러 개의 고름은 그대로다. 저장하지 않는다.
  - 거부(`money_full` 등): 창을 닫고 같은 곳으로 돌아간다. 여러 개 켜짐과 고른 물건은 그대로 두고, 이유를 알림 줄에 보인다. 저장하지 않는다.
  - 받아들임: 한 번 자동 저장하고, 소지금·판매 줄·설명·판을 지금 상태로 다시 맞춘다. 고름을 모두 지우고 여러 개를 끈다.
    - 커서 물건이 남아 있으면 그 물건에 둔다. 없어졌으면 앞 줄 번호와 새 마지막 줄 번호 가운데 작은 곳에 두고 보이게 내린다.
    - 목록이 비면 커서를 없애고 `shop.why.empty_sell`을 보인다.
  - 사건에 `unlocked`가 있으면 위 갱신 뒤에 입하 알림 창을 한 번 띄운다(사건의 진열 차례 그대로, 목록 커서 `"none"`). 닫으면 같은 판매 목록에서 `"cursor"`로 돌아간다.
- 판매 탭을 바꾸면 고름을 지우고 커서 0·맨 위로 간다. 여러 개 켜짐은 그대로다.
- 판매 화면에 새로 들어오면 소재 탭·커서 0·맨 위·여러 개 꺼짐이다.
- 원작과 다른 점: 줄은 종류마다 하나에 「N개」이다(D24). 고른 줄은 하늘색이다(§7.1). 여러 개로 고르면 그 줄의 가진 수를 다 판다.

### 8.9. 키 표(키보드 = 가상 키패드)

07 §9.7과 같은 방식이다. 키보드와 가상 키패드는 같은 `key_action`을 쓰고, 일하는 때는 캠프와 같다(독립 설계 검토 F2):
- 키보드는 반복이 아닌 첫 키 누름에서 한 번 일하고, 키를 뗄 때는 일하지 않는다. 반복과 Ctrl·Alt·Meta 조합은 삼키고 아무 일도 하지 않는다.
- 가상 키패드는 방향을 누르는 순간, 선택·취소를 그 단추 안에서 뗄 때 일한다.
- 할 일이 없는 키패드 단추는 흐리다(`pad_state`).

| 화면 | ↑↓ | ←→ | 선택 | 취소 | 그 밖의 키 |
|---|---|---|---|---|---|
| 뿌리 | 명령 커서(돌아감) | 흐림 | 커서 명령 | 상점 닫기 | `1`~`5` 그 명령 |
| 구매 갈래 | 갈래 커서(돌아감) | 앞·다음 대원 | 그 갈래 목록 | 뿌리로 | `1`~`4` 그 갈래, `Q`/`E` 대원 |
| 구매 목록 | 줄 커서 | 앞·다음 대원 | 커서 줄 사기 | 갈래로 | `Z`/`X`·`PageUp`/`PageDown` 앞·다음 탭(탭 줄이 있을 때), `Q`/`E` 대원 |
| 판매 목록 | 줄 커서 | 앞·다음 대원 | 팔기, 여러 개면 고름 켜고 끄기 | 뿌리로, 여러 개면 끄기 | `Z`/`X`·`PageUp`/`PageDown` 탭, `M` 여러 개·고른 것 팔기, `Q`/`E` 대원 |
| 확인·장착 물음 창 | 흐림 | 두 단추 사이 | 고른 단추 | 「아니오」 | |
| 수량 창 | 수량 ±1 | 두 단추 사이 | 고른 단추 | 「아니오」 | `PageUp` +10, `PageDown` −10 |
| 칸 고르기 창 | 칸 커서 | 흐림 | 그 칸에 끼기 | 끼지 않기 | |
| 입하 알림 | 흐림 | 흐림 | 닫기 | 닫기 | |

- `Enter`·키패드 `Enter`·`Space`가 선택이고, `Esc`·`Backspace`가 취소다. `Tab`은 쓰지 않는다(07 §9.4).
- 탭은 끝에서 감기지 않는다(원작 미확인, research 06 §2.2).
- 휴대폰은 탭·「여러 개」·창 단추를 직접 누른다. 키패드에 그 단추를 더하지 않는다.

### 8.11. 저장·디버그·S2 부품 고침

- **저장**: 받아들인 사기·팔기·장착 뒤 자동 저장한다. 캠프 저장 갈고리와 같은 길이다(`save_hook` → 탐색 화면 `_autosave`).
- **디버그 스냅숏**: `shop` 칸을 둔다.
  - 열림, 화면, 갈래, 탭, 대원, 커서, 줄(이름·오른쪽 글·흐림·고름), 여러 개.
  - 창 모드·고른 단추·수량, 소지금, 알림 줄.
  - 키패드 단추별 켜짐, 누를 수 있는 단추 이름(캠프 `buttons`와 같은 꼴).
- **S2 부품 고침**:
  - `ShopDialog`의 `yes_first` 기본값을 true로 바꾼다(D25). 시험도 고친다.
  - `open_confirm`에 [아이콘] 이름 머리 줄을 더한다(§8.6).
  - 새 모드 `slots`를 더한다(§8.7).
  - **입력 갈고리**(독립 설계 검토 F3): 화면에 붙인 창의 단추(예·아니오·확인·수량·칸)는 먼저 `ShopScreen.handle`에 요청한다. 화면이 열림·층 3 막힘·한 프레임 한 입력을 통과시킨 뒤에만 `ShopDialog.handle`이 일한다. 창을 먼저 닫고 `answered`에서 뒤늦게 거르지 않는다. 부품 혼자인 시험은 지금처럼 바로 `handle`을 불러도 된다.
  - **줄·탭도 같은 길**(독립 코드 검토 R1): `buy_list.route` → `handle("row", i)`, `buy_tabs.route` → `handle("tab", i)`(§7.3·§7.4). 화면이 거절하면(한 프레임 한 입력, 층 3 막힘, 창 열림, 갈 수 없는 줄·탭) 목록 커서와 고른 탭은 그대로다. 받아들인 뒤에만 화면이 커서·탭을 옮긴다.
- **문맥**: 화면의 문맥 글에는 창 모양뿐 아니라 물음의 목적(사기 확인·팔기 확인·장착 물음·칸 고르기·알림)과 대상 물건·대원이 들어간다. 같은 `confirm` 모양으로 사기 확인이 장착 물음으로 바뀌어도 누르기를 버린다.
  - 고른 줄(정렬한 물건 id)도 들어간다(독립 코드 검토 R2). 줄을 고르거나 끄면 바깥에서 누르고 있던 「여러 개」·키패드·「뒤로」 누르기를 버린다.
- **묶음 팔기 고정**(독립 코드 검토 R3):
  - 「고른 것 팔기」 확인 창을 열 때 팔 줄 `[{item, qty}]`(`ask_lines`)를 고정하고, 합계도 그 줄로 보인다. 「예」는 그 줄만 판다.
  - 창이 열린 동안 가방이 바뀌어(디버그 `supply` 등) 그만큼 갖고 있지 않으면 규칙이 거부한다(`not_owned` → `shop.why.not_now`). 저장하지 않고, 고름과 여러 개는 그대로다(F1 거부).
  - 창이 닫히면 답과 상관없이 비운다.
- **디버그 값의 출처**: 스냅숏의 `cursor.row`는 `buy_list.cursor`(화면만 바꾼다. 빈 목록이면 −1, D28-b), `tab`은 화면의 `tab`, `rows`는 화면의 `lines`다.
- **층 3 창**: 탐색 화면의 층 3 창이 열리고 닫힐 때 캠프·전투처럼 상점의 누르기도 버린다(`dungeon_screen.gd`의 창 신호에 상점을 더한다).
- **받아들임과 저장**(독립 설계 검토 F6):
  - 사기·팔기·장착 규칙이 받아들여지면, 저장에 실패해도 메모리 상태를 되돌리거나 같은 규칙을 다시 부르지 않는다.
  - 탐색 화면의 저장 실패 토스트·저장 중 표시를 그대로 보이고, 화면은 지금 메모리 상태로 맞춘 뒤 장착 물음·입하 알림 차례를 이어 간다.
  - 사기와 장착은 따로 끝나는 변경이고 각각 저장한다. 산 뒤의 저장에는 물건이 가방에 있다. 낀 뒤의 저장에는 새 장비와 가방으로 돌아온 옛 장비가 함께 들어 있다.

### 8.13. 원작과 다른 점(S3)

- 뿌리의 대화·장비 바꾸기는 흐리고 이유만 보인다(NPC·상점 안 장비는 S4·M3).
- 구매 갈래의 파티 카드는 폭이 모자라면(1280×720) 숨긴다. 대원은 오른쪽 판으로 보고 넘긴다(§8.4).

- 뿌리 명령 목록은 줄 64·간격 4다(원작 약 28, 64px 터치).
- 방어구 장착의 칸 고르기는 창으로 한다(원작은 판, 보고만).
- 확인 창 머리에 물건 이름 줄이 있다(창이 커서 줄을 덮는다).
- 판매 줄은 쌓아 보이고, 여러 개로 고르면 가진 수를 다 판다(D24).
- 고른 줄은 하늘색이다(원작 노랑, §7.1).

- 「여러 개」는 돈 위 표지(원작 Y MULTI)가 아니라 탭 줄 왼쪽 단추다.
- 입하 알림 창은 목록 자리 가운데에 뜬다(원작은 화면 왼쪽 절반).

- 캐릭터 판은 모든 능력치를 「지금 → 바꾸면」으로 보인다(캠프 장비 화면과 같다). 원작은 공격·방어의 화살표만 보인다.

### 8.14. 구현 메모(S3, 2026-10-25)

명세가 정하지 않아 구현이 정한 것이다. 코드가 기준이다.

- **입구**: `DungeonScreen.debug_tools()`(디버그 주소 또는 네이티브 디버그 실행)가 「상점」 단추·`open_shop` 요청·캠프 임시 보급을 함께 정한다. 「상점」은 안내 줄의 「지도」 뒤다. 캠프와 상점은 서로 열려 있으면 열리지 않는다.
- **쪽**: `page`는 `root`·`branch`·`buy`·`sell`이다.
  - 갈래에는 상점 문패가 그대로 있고 「뒤로」는 없다. 갈래의 뿌리 명령 줄은 번호 없이 쓴다(숫자 키는 하위 목록 것).
  - 판매에 들어오면 `_open_sell()`이 소재 탭·커서 0·여러 개 꺼짐·고름 없음으로 맞춘다.
- **설명 띠**:
  - 갈래: 첫 줄 `shop.desc.branch`, 둘째 줄은 알림이 있으면 알림, 없으면 커서 갈래 설명.
  - 판매: 첫 줄 `shop.desc.sell`(여러 개면 `shop.desc.multi`), 둘째 줄은 알림 또는 빈 목록이면 `shop.why.empty_sell`.
- **설명 창**:
  - 장비: 첫 줄 값(「공격 +8 · 베기」), 머리글자 칸(`ShopFrame.show_desc(…, badges)`, 색 `UiTheme.SHOP_BADGE_*`). 둘째 줄은 이유가 있을 때만이다(§8.5).
  - 소재: 본문은 종류 「소재」(`shop.tab.material`).
- **못 끼는 대원**: `buy_unfit`과 판 흐림은 직업 규칙(`EquipDef.fits`)만 본다. 직업은 맞지만 `best_slot`이 −1이면 보통 확인 글이고, 비교·표시 칸·장착 물음이 없다.
- **사기 전 이유 차례**: 규칙 차례(품절 → 돈 → 가방).
- **알림**: 장착이 받아들여지면 `growth.event.equipped`(캠프 문구)를 보인다. 사기만 하면 알림 없이 소지금과 줄이 바뀐다.
- **창 입력**: `ShopDialog.route`가 있으면 창 단추는 `ShopScreen.handle("dialog", [종류, 값])`로 간다. 화면은 `ask`(`buy`·`equip`·`slots`·`sell`·`sell_multi`·`notice`)·`ask_item`·`ask_member`로 물음과 대상을 고정하고 문맥 글에 넣는다. 묶음 팔기는 팔 줄까지 `ask_lines`로 고정한다(§8.11).
- **같은 꼴 점검**(독립 코드 검토 R1·R3 뒤):
  - 받아들이기 전에 스스로 바뀌는 부품은 목록·탭뿐이었다(고침). `FacilityList`·`CharPanel` 화살표·「여러 개」·「뒤로」·키패드는 신호만 내고, 창은 이미 `route`를 쓴다. 끌기는 내린 위치만 바꾼다.
  - 「예」가 보인 것보다 더 하는 창은 묶음 팔기뿐이었다(고침). 사기 확인·한 줄 팔기·장착 물음·칸 고르기는 연 때 대상(`ask_item`·`ask_member`·창의 `qty`)을 고정하고, 상태가 바뀌면 규칙이 거부할 뿐이다.
- **칸 고르기**: `ShopDialog.open_slots(rows, first)`, 입력 `slot_move`(±1, 끝에서 멈춤)·`confirm`(칸 번호 또는 커서)·`cancel`, 신호 `slot_picked(slot)`(끼지 않으면 −1). 커서는 칸 1~3만 돌고, 「아니오」는 노랑이 되지 않는다.
- **여러 개**: `MultiButton`(16,166 200×64)은 판매에서만 보인다. 켜짐은 `checked`, 글은 `shop.multi.sell`이다.
  - 고른 줄이 없을 때 다시 누르면 끈다. 있으면 묶음 확인 창(머리 줄 없음)이다.
  - 커서 줄은 노랑이 이기고, 고름은 아이콘 칸 테두리로 보인다.
  - 여러 개가 켜져 있으면 첫 취소가 끄고 고름을 지운다. 다음 취소는 뿌리로 가고 커서는 「팔기」다.
- **입하 알림**: 판매 한 번에 한 번이다. `unlocked` 사건의 물건을 진열 차례로 보인다. 선택·취소 모두 닫고, 닫아도 저장하지 않는다.
- **장비 탭(판매)**: `gear_bag`만 자료 차례로 보인다(낀 장비는 가방에 없다). 판은 비교도 표시 칸도 없다.
- **키**: `M`은 판매에서 여러 개·고른 것 팔기다. 구매 목록에서는 삼킨다. 키패드 흐림은 빈 목록의 ↑↓·선택, 대원이 하나뿐일 때 ←→다.

  - `FacilityList.row_gap`·`inner_pad`(6·6), `content_height(n, gap, pad)`, `show_rows(…, dim)`.
