# 제작 계획: 그림 에셋과 단계

상태: 초안 (2026-10-16).

## 1. 그림 에셋

### 1.1. 원칙

- 그림은 GPT 이미지 생성(Paseo 프로필 「이미지 작업 : 지피티」)으로 만든다. 생성 뒤 조정자가 직접 열어 검수하고, 통과한 것만 `assets/`에 넣는다.
- 그림체 기준은 `~/projects/artstyle_reference`의 그림체다. 원작 스타일을 드러내는 방향(01 §1.2)에서는 원작 캐릭터 일러스트의 결을 분석한 `thick-lineart-hard-cel`을 바탕으로 한다(D6 확정). 기준 문서(`styles/<이름>/STYLE.md`)의 특징 서술과 참고 이미지를 생성 요청에 함께 넘긴다.
- 생성 요청에 작품명 구절(`in the vein of Etrian Odyssey character designs`, `unofficial Etrian Odyssey fan game`)과 원작 직업 계열 설명(예: `the series' classic paladin-type shield class`)을 넣는다. 현역 일러스트레이터 이름은 GPT 이미지가 거절하거나 무시할 수 있어 넣지 않고, 특징 서술과 참고 이미지로 대신한다(`thick-lineart-hard-cel/STYLE.md` 「화풍 기준 이름 넣기」).
- `thick-lineart-hard-cel/generated/eo0*_*.png`(원작 1편 직업을 이 그림체로 그린 시험작)는 원작 결을 잡는 스타일 참고로 넘긴다. 게임의 직업 초상화는 이 게임의 직업(04 §2.3)으로 새로 그린다.
- 직업 초상화끼리 한 파티처럼 보이게 하려면, 이 게임의 기준 그림 한 장을 다섯 번째 참고("world look reference": 기계 팔다리·천 옷·홀로그램을 그리는 방식만 따르고 얼굴·장비·문장은 따라 하지 않게 적음)로 넘긴다(04 §3.5에서 효과 확인). 문장 같은 표식이 옮겨 올 수 있어 새 캐릭터에는 "문장 없음"을 적는다.
- 그림체 참고 이미지의 인물 특징(머리색·브릿지·표정)이 새 캐릭터로 옮겨 올 수 있다. 새 캐릭터와 머리색·표정이 겹치는 참고 그림은 그 생성에서 뺀다(04 §3.1.1).
- 참고 이미지(`reference/`)는 이 저장소에 넣지 않는다. 저장소는 공개이고, 참고 이미지는 사용자가 따로 모은 자료다.

### 1.2. 그림체 선택 (D6 확정)

| 그림체 | 특징 | 이 게임에서의 장단점 |
|---|---|---|
| `flat-lineless-gouache` | 외곽선 없는 평면 채색, 과슈풍 그림자, 제한 팔레트(검정·흰색·금색 + 강조색 하나), 가늘고 긴 다리, 큰 무기 | 원작 결과 거리가 멀어, 원작 스타일을 드러내는 지금 방향과 맞지 않는다. 제한 팔레트라 계층별 색 주제와 미궁 텍스처를 맞추기는 쉽다. 캐릭터 분위기는 동화풍으로 가볍다 |
| `thick-lineart-hard-cel` | 굵은 검정 외곽선, 각진 셀 그림자, 검은 그림자 덩어리, 4~5등신 | 원작 캐릭터 일러스트를 기준으로 분석한 그림체라 원작 팬이 바로 알아본다. 굵은 선과 검은 그림자 덩어리가 기계 몸의 무게와 홀로그램 발광의 대비를 살린다 |

- **확정(2026-10-16, D6·D9):** **`thick-lineart-hard-cel` 바탕 + 사이버 비중 B 반반**(04 §3.3~3.5). 원작 스타일을 드러내는 팬 후속작 방향(`00-decisions.md`)에 맞춘 선택이다.
- 갱신 2(2026-10-16): 그 방향이 정해져 `thick-lineart-hard-cel` 바탕 위에서 사이버 비중을 3안으로 비교했다(04 §3.4).
- 갱신 1(2026-10-16): 사이버펑크 + 홀로그램 판타지 방향이 정해져 `thick-lineart-hard-cel` 바탕 + 사이버·홀로그램 규칙을 먼저 시험하기로 했다(04 §3.2).
- (처음 제안, 폐기) 주력은 `flat-lineless-gouache`. 원작과 거리를 두던 "장르 모티브, 독자 표현" 방침 때의 판단이다.
- 두 그림체를 한 화면에 섞지 않는다.

### 1.4. 확인할 기술 조건

- **투명 배경** (M0 확인): 흰 배경으로 생성해 검수한 뒤, 그 그림을 편집으로 투명 배경으로 바꾼다(`transparent_background`, 편집 대상 1장만 참고로). 홀로그램이 반투명으로 남는 방법은 이것뿐이었다. 생성 결과의 알파 최댓값이 253~254라 253 이상은 255로 올린다. 투명 영역의 RGB 는 검정·금색이 남아 있을 수 있어 Godot 가져오기의 `process/fix_alpha_border`(기본 켜짐)를 끄지 않는다.
- **이음새 없는 텍스처** (M0 확인): 생성 결과를 `python3 tools/tile_check.py check` 로 재고 `preview` 로 바둑판을 본다. 무늬가 이어져 있으면 `fix --size 512` 로 가장자리 줄만 지우고 줄인다(주기+평활 분해, 무늬는 그대로). 무늬가 가장자리에서 끊겨 있으면 다시 생성한다. 오프셋 합성은 그림 가운데 절반이 한 장 안에서 두 번 반복되고 겹친 띠가 흐려져서 쓰지 않는다. 게임에서는 밉맵을 켠다(`mipmaps/generate=true`, `detect_3d/compress_to=0`).
- **같은 캐릭터 일관성**: 외형 2종은 같은 직업의 다른 사람이므로 일관성 요구가 낮다. 표정 차분이 필요해지면 그때 다시 정한다.

## 2. 단계

각 단계는 수용 기준을 실제 실행 결과(시험 로그·캡처·휴대폰 확인)로 판정한다.

### M0. 기반 (짧게)

- Godot 프로젝트 생성(Compatibility, 1280×720), 폴더 구조(02 문서 §4), 헤드리스 시험 실행기.
- 웹 내보내기 설정(스레드 없음). 이 기기에서 내보내고 Chromium으로 열어 캡처, `cloudflared`로 휴대폰에서 열기.
- `docs/CLOUD_TESTS.md`와 클라우드 실행 경로(Claude 클라우드).
- 그림 생성 시험: 투명 배경·이음새·그림체 비교(D6). 모두 끝남(아래 진행 기록).

진행 기록 (2026-10-16):

| 항목 | 결과 |
|---|---|
| 프로젝트·첫 장면 | Compatibility 렌더러, 1280×720. 3D 복도 + 한글 글자 |
| 시험 실행기 | `tests/run.gd`, 난수 결정성 시험 2개 통과, 일부러 넣은 실패 시험에서 종료 코드 1 확인 |
| 웹 내보내기 | 스레드 없는 템플릿, 이 기기에서 34초. `index.wasm` 39.5MB(gzip 10.1MB), `index.pck` 1.4MB, `index.js` 0.28MB(gzip 0.07MB) |
| 브라우저 캡처 | Chromium 153 + Xvfb + ANGLE(llvmpipe), 컨텍스트 잃음 없음, 오류 없음, 한글 표시 정상 |
| 그림체 | D6·D9 확정: `thick-lineart-hard-cel` + 사이버 비중 B. 기준 그림 3장(04 §3.5) |
| 이음새 없는 텍스처 | 첫 계층 벽·바닥을 1회씩 생성(`assets/concept/tests/stratum1_*.png`, 요청은 1024였지만 1254×1254로 나옴, 도구에 크기 인수가 없다). 2×2로 이어 원본 해상도로 봐도 무늬가 끊긴 곳은 없다. 수치로는 가장자리 줄이 그림에서 가장 튄다(`tools/tile_check.py check` 이웃비 1.4~2.0) → `tile_check.py fix`(주기+평활 분해)로 0.3~0.5. 512 축소본(`assets/textures/stratum1/`)을 M0 복도에 입혀(세계 좌표 삼면 투영, 밉맵) 웹 빌드 캡처에서 칸 사이 이음새가 보이지 않음을 확인. `index.pck` 2.6MB |
| 투명 배경 | 도구가 실제 알파를 준다(`transparent_background`). 투명 배경으로 바로 생성하면 홀로그램이 거의 불투명하다(방패 알파 250/255). 검수한 흰 배경 그림(B2)을 편집하면 인물이 그대로이고 홀로그램이 반투명으로 남는다(방패 87). 이 기기에서 흰 배경을 칠하기로 지우면 홀로그램이 우윳빛 불투명으로 남는다. 두 생성 결과 모두 알파 최댓값이 254(얼굴·옷 253)다. → 초상화 경로: 흰 배경으로 생성·검수 → 편집으로 투명 배경 → 알파 253 이상을 255로(§1.4) |
| 가져오기 | Godot 가 `node_modules/`(playwright SVG)·`build/` 까지 가져오다 같은 SVG 를 되풀이하며 멈췄다 → `.gdignore`(npm `postinstall`·`tools/export_web.sh` 가 만든다) |
| 클라우드 경로 | `docs/CLOUD_TESTS.md`, `tools/cloud/test.sh`(Claude 클라우드, lastorigin-fan 본보기). 시범 실행은 시뮬레이션이 생기는 M2 때 처음 돌린다(사용자 결정) |
| 휴대폰 실기 확인 | 갤럭시 가로 화면, `tools/serve_web.py`(gzip, 처음 받는 양 약 13MB) + `cloudflared` 임시 주소. 처음에는 가까운 벽·바닥이 먼 꼭짓점에서 퍼지는 줄무늬로 깨졌다(PC 는 정상). 카메라가 첫 칸의 경계 면(z = +1)에 있어 그 면의 정점이 카메라 깊이 0(w = 0)이었다. 줄무늬가 모이는 두 점이 계산한 꼭짓점 위치와 맞았다. 카메라를 칸 가운데로 옮긴 뒤 휴대폰에서 정상 확인(사용자) |
| 남음 | 없음(클라우드 시범 실행은 M2) |

수용 기준: 빈 장면이 브라우저와 휴대폰에서 뜬다. `tests/run.gd`가 헤드리스로 돌고 실패를 종료 코드로 알린다. 웹 빌드 크기를 잰다.

### M1. 탐색 시제품

- 한 층(문자 격자 데이터), 이동·회전·평행 이동, 벽·문·일방통행·숨은 통로·피해 바닥·미끄러운 바닥.
- 카메라는 칸 가운데에 둔다. 이동 연출 중에도 칸 경계 면(벽·바닥 정점이 있는 평면)에 정확히 멈추는 프레임이 없게 한다(가운데→가운데 보간의 중간점 t = 0.5가 정확히 경계다). 경계 면에 정점이 있으면 휴대폰 GPU 에서 그 삼각형이 줄무늬로 깨진다(M0 진행 기록 「휴대폰 실기 확인」).
- 지도 자동 기록(3단계 옵션)과 수동 편집(벽 선·바닥 색·아이콘·메모·실행 취소).
- 위험도 게이지와 인카운트 발생(전투는 자리표시: "전투 발생" 후 승리 처리).
- 저장·불러오기·내보내기.

수용 기준: R1 §4.6의 항목 중 이동 결정성, 지도와 세계 상태 분리, 일방통행·지름길 상태의 저장 유지, 마우스·키보드·터치 오작동 없음, 새로고침 후 복구.

### M2. 전투 시제품

- 전투 규칙 코어(헤드리스), 직업 4개(방패지기·검객·약초사·술사), 적 6종, 전후열, 상태이상 3종 + 봉인 3종, 강화·약화 슬롯.
- 전투 화면(명령 입력, 행동 실행 연출, 전투 로그).
- 밸런스 시뮬레이션 첫 실행(클라우드).

수용 기준: R2 §4.6의 최소 검증 사례(전후열 사거리, 봉인 후 불발, 상태 덮어쓰기, 네 번째 강화, 조건부 드롭의 처치 순간 상태)가 시험으로 통과. 시뮬레이션에서 초반 일반전 평균 3~5턴.

### M3. 수직 슬라이스

- 마을 시설 5개, 3개 층, FOE 3종(전투 난입 포함), 채집 3종, 상점 해금, 의뢰 3개, 보스 1체, 직업 6개.
- 생성 그림 적용, 글꼴, 효과음·음악(공개 라이선스 또는 생성).

수용 기준: 새 게임부터 보스 처치까지 막힘 없이 진행(사람 플레이 1회 + 자동 경로 시험). 휴대폰 가로에서 한 원정을 끝까지 조작할 수 있음.
