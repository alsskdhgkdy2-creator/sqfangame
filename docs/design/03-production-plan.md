## 1. 그림 에셋

### 1.1. 원칙

- 그림은 GPT 이미지 생성(Paseo 프로필 「GPT · 시각」, 옛 이름 「이미지 작업 : 지피티」)으로 만든다. 후보는 저장소 밖 작업 폴더(`/root/workspace/sqfangame-art/`)에 만들고, 조정자가 직접 열어 검수해 통과한 것만 `assets/`에 넣는다(D29 ③).
- 그림체 기준은 `~/projects/artstyle_reference`의 그림체다. 원작 스타일을 드러내는 방향(01 §1.2)에서는 원작 캐릭터 일러스트의 결을 분석한 `thick-lineart-hard-cel`을 바탕으로 한다(D6 확정). 기준 문서(`styles/<이름>/STYLE.md`)의 특징 서술과 참고 이미지를 생성 요청에 함께 넘긴다.
- 생성 요청에 작품명 구절(`in the vein of Etrian Odyssey character designs`, `unofficial Etrian Odyssey fan game`)과 원작 직업 계열 설명(예: `the series' classic paladin-type shield class`)을 넣는다. 현역 일러스트레이터 이름은 GPT 이미지가 거절하거나 무시할 수 있어 넣지 않고, 특징 서술과 참고 이미지로 대신한다(`thick-lineart-hard-cel/STYLE.md` 「화풍 기준 이름 넣기」).
- `thick-lineart-hard-cel/generated/eo0*_*.png`(원작 1편 직업을 이 그림체로 그린 시험작)는 원작 결을 잡는 스타일 참고로 넘긴다. 게임의 직업 초상화는 이 게임의 직업(04 §2.3)으로 새로 그린다.
- 직업 초상화끼리 한 파티처럼 보이게 하려면, 이 게임의 기준 그림 한 장을 다섯 번째 참고("world look reference": 기계 팔다리·천 옷·홀로그램을 그리는 방식만 따르고 얼굴·장비·문장은 따라 하지 않게 적음)로 넘긴다(04 §3.5에서 효과 확인). 문장 같은 표식이 옮겨 올 수 있어 새 캐릭터에는 "문장 없음"을 적는다.
- 그림체 참고 이미지의 인물 특징(머리색·브릿지·표정)이 새 캐릭터로 옮겨 올 수 있다. 새 캐릭터와 머리색·표정이 겹치는 참고 그림은 그 생성에서 뺀다(04 §3.1.1).
- 참고 이미지(`reference/`)는 이 저장소에 넣지 않는다. 저장소는 공개이고, 참고 이미지는 사용자가 따로 모은 자료다.

### 1.4. 확인할 기술 조건

- **투명 배경** (M0 확인): 흰 배경으로 생성해 검수한 뒤, 그 그림을 편집으로 투명 배경으로 바꾼다(`transparent_background`, 편집 대상 1장만 참고로). 홀로그램이 반투명으로 남는 방법은 이것뿐이었다. 생성 결과의 알파 최댓값이 253~254라 253 이상은 255로 올린다. 투명 영역의 RGB 는 검정·금색이 남아 있을 수 있어 Godot 가져오기의 `process/fix_alpha_border`(기본 켜짐)를 끄지 않는다.
- **이음새 없는 텍스처** (M0 확인): 생성 결과를 `python3 tools/tile_check.py check` 로 재고 `preview` 로 바둑판을 본다. 무늬가 이어져 있으면 `fix --size 512` 로 가장자리 줄만 지우고 줄인다(주기+평활 분해, 무늬는 그대로). 무늬가 가장자리에서 끊겨 있으면 다시 생성한다. 오프셋 합성은 그림 가운데 절반이 한 장 안에서 두 번 반복되고 겹친 띠가 흐려져서 쓰지 않는다. 게임에서는 밉맵을 켠다(`mipmaps/generate=true`, `detect_3d/compress_to=0`).
- **같은 캐릭터 일관성**: 외형 2종은 같은 직업의 다른 사람이므로 일관성 요구가 낮다. 표정 차분이 필요해지면 그때 다시 정한다.

### M1. 탐색 시제품

상세 명세: `05-m1-exploration.md`.

- 한 층(문자 격자 데이터), 이동·회전·평행 이동, 벽·문·일방통행·숨은 통로·피해 바닥·미끄러운 바닥.
- 카메라는 칸 가운데에 둔다. 이동·회전 연출 중에도 그려지는 정점이 카메라 깊이 0 근처에 오는 프레임이 없게, 매 프레임 실제 정점으로 검사해 앞뒤로 살짝 비켜 둔다(05 §9.2.1). 가운데→가운데 보간의 중간점 t = 0.5는 정확히 경계 면이고, 90° 회전의 중간(45°)에서는 대각선 위 칸 모서리 정점들이 깊이 0이 된다. 그런 정점이 있으면 휴대폰 GPU 에서 그 삼각형이 줄무늬로 깨진다(M0 진행 기록 「휴대폰 실기 확인」).
- 지도 자동 기록(3단계 옵션)과 수동 편집(벽 선·바닥 색·아이콘·메모·실행 취소).
- 위험도 게이지와 인카운트 발생(전투는 자리표시: "전투 발생" 후 승리 처리).
- 저장·불러오기·내보내기.

수용 기준: R1 §4.6의 항목 중 이동 결정성, 지도와 세계 상태 분리, 일방통행·지름길 상태의 저장 유지, 마우스·키보드·터치 오작동 없음, 새로고침 후 복구.

### M2. 전투 시제품

### M2.7. 화면 위에 뜨는 UI·원작 배치 (D23, 2026-10-24)

화면(3D 시야·전투 배경·시설 그림)은 늘 화면 전체이고 UI는 그 위에 뜬다. 짜임은 찾아 둔 원작 HD 화면을 그대로 옮긴다(research 05 §2). 그림이 없는 것은 같은 자리·크기의 자리표시로 둔다. 단계는 난이도 순이다.

- R1 겹침 골격 + 탐색(원작: 탐색 지도 닫힘·지도 펼침): Godot `CanvasLayer` 층(세계·HUD·창·모달·알림)과 앵커 배치. 3D 시야는 어느 모드에서도 줄이지 않는다(옆 판은 렌즈 이동, research 05 §1.2). 기본은 지도 닫힘: 왼쪽 위 층 문패(다이얼 자리), 오른쪽 위 미니맵, 오른쪽 아래 위험 보석 자리표시, 왼쪽 아래 이동 단추·안내 줄 단추. 지도 펼침은 오른쪽 약 43% 전체 높이 판(층 전체 보기 + 확대 그리기 격자 + 세로 도구 열 + 아이콘 판). 탐색 중 상태 칸은 없앤다(원작에 없음, 파티 상태는 캠프·전투에서).
- R2 캠프(원작: 캠프·상태·스킬 목록·스킬 트리·장비·소지품·옵션·불러오기): 「파티」와 「메뉴」를 「캠프」 하나로 묶고, 하위 화면을 원작 짜임으로. 캠프 뿌리 화면의 원작 그림은 공식 자료·기사 사진 모음에서 끝내 찾지 못했다(research 05 §2.2). 사용자 결정(2026-10-24): 원작 시설 화면 짜임(맨 위 설명 띠, 왼쪽 명령 목록, 아래 파티 카드, 배경 화면 전체)으로 **추정**해 만들고 추정이라고 적는다. 하위 화면(상태·스킬·장비·소지품·기록)은 각각의 원작 그림을 따른다.
