# 기술 계획

상태: 초안 (2026-10-16). M0(아래 §8)에서 실제로 확인한 뒤 고친다.

## 1. 엔진과 대상

| 항목 | 결정 | 이유·확인 |
|---|---|---|
| 엔진 | Godot 4.7.2-stable (`godot` 명령, 스크립트에서는 `${GODOT:-godot}`) | 이 기기에 설치됨(`godot --version` → `4.7.2.stable.official.ed1daf0bf`) |
| 언어 | GDScript만 | Godot 4의 C# 프로젝트는 웹으로 내보낼 수 없다(R1 §2.13, Godot 웹 내보내기 문서) |

## 2. 화면 구성

- 기준 해상도 1280×720, `canvas_items` 늘이기, 가로 우선(D3 결정에 따라 바뀜).
- 미궁 화면: 왼쪽 약 60%에 1인칭 시야, 오른쪽에 지도·파티 상태. 휴대폰 가로에서는 지도를 접었다 펼친다.
- 전투 화면: 1인칭 시야 위에 적 그림(2D)을 전후열로 배치하고, 아래에 파티 5명 상태 칸.
- 마을: 시설 그림 한 장 + 메뉴.

## 3. 1인칭 미궁 표현

| 방식 | 장점 | 단점 |
|---|---|---|
| **3D 모듈 조각 (제안)** | 이동·회전 애니메이션이 자연스럽다. 벽·바닥·천장 텍스처 몇 장으로 층 전체를 만든다. 조명·안개로 계층 분위기를 쉽게 바꾼다 | 3D 조각과 텍스처 제작이 필요 |
| 2D 원근 그림 겹치기 (고전 방식) | 그림체를 그대로 살린다 | 거리·방향별 조각 그림이 수십 장 필요하고, 생성 이미지로 조각끼리 원근을 정확히 맞추기 어렵다 |

- 제안: 미궁은 **3D**(단순 상자 조각 + 생성 이미지로 만든 이음새 없는 텍스처), 캐릭터·적·마을·UI는 **2D 그림**으로 한다.
- 격자 1칸 = 2m 상자. 이동은 약 0.2초 보간, 입력은 보간 중에 하나까지 미리 받는다.
- 층 데이터에서 벽·문 메시를 만들어 `MultiMeshInstance3D`로 그린다(조각 종류별 하나).
  - M1에서 재질별로 합친 메시(`SurfaceTool`)로 바꿨다(05 §9.2). 칸마다 면 구성이 달라 MultiMesh 이점이 적고, 휴대폰 GPU 줄무늬를 피하는 카메라 보정에 실제 정점 목록이 필요하다.

## 4. 코드 구조

규칙(게임 논리)과 표현(노드·화면)을 나눈다. 규칙 코드는 노드에 의존하지 않아서 헤드리스 시험과 대량 시뮬레이션을 할 수 있다.

```
project.godot
src/
  core/        # 노드 없는 순수 규칙 (RefCounted)
    rng.gd               난수 (시드·상태 저장 가능)
    dungeon/             FloorModel, Cell, Edge, 이동 판정, 지형 효과, 지도 자동 기록
    foe/                 FOE 상태기계, 시야, 경로
    encounter.gd         위험도·출현 표
    battle/              BattleState, 행동 큐, 피해·명중·상태이상 계산, 적 AI, 전투 로그
    party/               캐릭터, 직업, 스킬 트리, 장비, 성장
    town/                상점 해금, 의뢰 상태, 여관, 날짜
    save/                저장 직렬화, 스키마 이전
  data/        # 정의 데이터 읽기·검증 (JSON → 타입 객체)
  game/        # 노드·장면: 미궁 시야, 지도 편집기, 전투 화면, 마을, 메뉴
  ui/          # 공용 UI 부품, 테마
data/          # 정의 데이터 (JSON)
  classes/ skills/ enemies/ items/ floors/ encounters/ quests/ text/
assets/        # 생성 이미지·소리 (출처 기록 포함, 03 문서)
tests/         # 헤드리스 시험
tools/         # 데이터 검증·시뮬레이션·내보내기·캡처 스크립트
```

### 4.1. 정의 데이터

- JSON으로 쓴다. 사람과 에이전트가 고치기 쉽고 diff가 읽힌다. 읽을 때 형식 검사를 하고, 틀리면 파일·필드 이름을 붙여 실패시킨다.
- 모든 정의에 바뀌지 않는 ID(`skill.striker.heavy_blow` 형식)를 둔다. 화면 문구는 `data/text/ko.json`에 따로 두어 번역·문구 수정이 데이터를 건드리지 않게 한다.
- 스킬 정의는 R2 §4.2의 필드 분리를 따른다: 피해 속성, 공격 능력치, 명중 능력치, 사거리, 대상, 사용 부위, 필요 무기, 우선 그룹, 레벨별 비용·위력 표.
- 층 정의: 칸 격자는 사람이 읽을 수 있는 문자 격자로 쓰고, 문·일방통행·기믹·FOE·이벤트는 좌표 목록으로 쓴다. 층이 많아지면 Godot 편집기 안에 간단한 층 편집기를 만든다(M3 이후).

### 4.2. 결정적 실행

- 모든 무작위는 `core/rng.gd` 하나를 거친다. 저장할 때 난수 상태를 함께 저장한다(R2 §4.6).
- 같은 시드와 같은 입력열이면 같은 결과가 나와야 한다. 이것을 시험으로 고정한다(R1 §4.6 수용 기준).
- 전투 로그는 판정 이유(명중률, 피해 계산 단계, 상태이상 확률)를 남긴다. 디버그 화면에서 볼 수 있게 한다.

### 4.3. 상태 소유

- 세계 상태(문 개방·장치·상자·FOE·의뢰·상점)는 `WorldState` 하나가 가진다. 화면 노드는 읽기만 하고 변경은 규칙 함수를 거친다.
- 플레이어 지도(`MapAnnotation`)와 방문 기록(`ExplorationKnowledge`)은 세계 상태와 분리한다(R1 §4.1).

## 5. 저장

- `user://`(웹에서는 브라우저 IndexedDB)에 JSON으로 저장한다. 스키마 버전을 넣고, 이전 판 저장을 새 판으로 옮기는 함수를 둔다.
- 웹에서는 저장 파일 내려받기·올리기를 둔다(`JavaScriptBridge`). 브라우저 저장소는 사용자가 지우거나 브라우저가 정리할 수 있다(Godot 웹 문서, R1 §2.13).
- 쓰기 실패에 대비해 직전 정상 저장을 하나 더 보관한다.

## 6. 웹 특이사항

- 오디오는 첫 사용자 입력 뒤에 켠다(브라우저 자동 재생 정책).
- 탭이 비활성이면 멈춘다. 이동 중 상태가 어긋나지 않게 규칙 상태는 프레임과 무관하게 진행한다.
- 한국어 글꼴: Noto Sans KR 같은 공개 글꼴을 필요한 글자만 남겨 줄인다(이 기기에 `pyftsubset` 있음). 웹 다운로드 크기를 줄인다.
- 초기 다운로드 목표: 압축 후 30MB 이하(M0에서 빈 프로젝트 크기를 먼저 잰다).

## 7. 시험과 검증

| 종류 | 내용 | 어디서 |
|---|---|---|
| 규칙 단위 시험 | `godot --headless -s tests/run.gd`. 외부 애드온 없이 작은 자체 실행기로 시작 | 이 기기 (수 초~수십 초) |
| 데이터 검증 | 모든 JSON을 읽어 형식·ID 참조·도달 가능성(층의 계단까지 경로) 검사 | 이 기기 |
| 결정성 시험 | 고정 시드 + 입력열 → 이동·FOE 위치·전투 결과 해시 비교 | 이 기기 |
| 전투 밸런스 시뮬레이션 | 파티 구성 × 적 편성 × 수천 판, 평균 턴 수·전멸률·TP 소모 | **클라우드** (`claude-cloud-test`, 공통 규칙 `cloud-tests.md`). 전투 규칙은 정수만 쓴다. 같은 Godot 판·같은 커밋·같은 설정이면 같은 시드의 결과가 기계가 달라도 같아야 한다(결과 해시로 비교, 06 §4.3·§7.6). 허용 범위는 판 수가 다른 통계 비교에만 쓴다(실수 연산을 쓴 lastoridot 에서는 머신마다 결과가 달랐다) |
| 웹 내보내기 | `godot --headless --export-release "Web" build/web/index.html` | 이 기기는 작은 프로젝트일 때만, 커지면 클라우드 |
| 화면 확인 | 헤드리스 Chromium(playwright-core)으로 내보낸 페이지를 열어 캡처. WebGL이라 `headless-webgl` 스킬 조건을 따른다 | 이 기기 / 클라우드 |
| 휴대폰 확인 | `cloudflared` 임시 주소로 실제 휴대폰에서 열기 | 사용자 |

- 무거운 로컬 실행은 서버 전체에서 하나씩만 한다.
- 이 저장소의 클라우드 실행 경로는 M0에서 `docs/CLOUD_TESTS.md`로 만든다.
